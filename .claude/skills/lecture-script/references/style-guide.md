# 原稿スタイルガイド｜語尾ルール＋「ドラフト→実収録」差分パターン

田川先生の **実際の収録（動画1, 第1回）** と **元のドラフト原稿** を突き合わせて抽出した校正方針。
新規ドラフトを書くときも、収録を反映するときも、ここに寄せる。**実収録を反映するたびに追記して育てる**生きたガイド。

---

## A. 語尾・文体ルール

読み上げ原稿は **declarative / instructional**（言い切り・指示）に寄せる。話し言葉の弱い・冗長な語尾を整理する。

**多用しない語尾**（推量・遠慮・冗長）
- 「〜と思います」「〜できればと思います」「〜ありがたいです」「〜結構です」「〜と思ってください」

**置換の方針**
| 用途 | 寄せる語尾 |
|---|---|
| 学生への依頼 | 「〜してください」 |
| 勧誘・提案 | 「〜しましょう」 |
| 事実・説明 | 「〜します」「〜です」 |
| 能力・到達 | 「〜できる」「〜できること」 |

**残すもの（硬くしすぎない）**
- 一人称の所感：「〜と感じています」「悩んでいるところですが」
- 温かい結語：「どうぞよろしくお願いいたします」
- 問いかけ：「〜でしょうか」
- 同じ語尾を連続させない（体言止め・問いかけを混ぜて単調さを回避）

**実際の before → after（第1回 動画1）**
- 受講されていると思います → 受講されています
- 進めていただければと思います → 進めてください
- 早めに見ておくとよいと思います → 早めに視聴しておきましょう
- 視聴いただけるとありがたいです → 視聴してください
- ワークがあると思ってください → ワークがあります
- 大いに使って結構です → 大いに使ってかまいません
- Moodleに記入いただけるとありがたいです → Moodleに記入してください
- ご説明できればと思います → ご説明します
- お話しできればと思います → お話しします
- 切り開いていければと思います → 切り開いていきましょう

## B. 「ドラフト → 実収録」差分パターン（＝今後の原稿作成の指針）

ドラフトを書くときに **あらかじめこう書いておく**と、実際の語りに近くなり、反映時の手戻りが減る。

1. **冒頭で名乗る**：表紙の原稿に「挨拶＋氏名＋所属＋歓迎」を入れる。
   （実収録は表紙で「国際未来教育基幹の田川です」と先に名乗ってから本題に入った）

2. **受講者を限定しない**：「皆さんの多くは研究者を目指している」→「研究者を目指す方も、高度な専門職を目指す方も。どんなキャリアでもAIは無視できない」のように **対象を広く取る枕**を置く。

3. **自己紹介スライドは要点だけ**：詳細な経歴の列挙（専門分野を複数・博士論文の内容など）は語られず、**要点に絞られた**（分野／幅広い手法＋プログラミングで苦労／AIで先へ）。詳細はスライド側に任せ、原稿は短く。

4. **ツール固有名は「何をするか」で言う**：「Colab演習」→「お手元で生成AIのミニチュアをつくる演習」。固有名詞より動作で表現。

5. **運用・進行の一言を足す**：ドラフトに無くても「ここまではオンデマンドが中心」「シラバスをよく読んで」など、**視聴・進行の案内**が即興で入る。各回の位置づけ＋運用の一言を原稿に用意しておく。

6. **他回・課題への相互参照を添える**：「仕組みは第3回に詳しく」「倫理はワークの一つ目で」など、**トピックの参照先**を流れスライドで一言添える。

7. **厳しい/ペナルティ表現は口頭で和らぐ**：ドラフトの「申告と利用が食い違えば課題を0点」は **収録では語られず**、申告のお願いに留まった。罰則的な文は原稿に残すか口頭で和らげるか、**毎回ユーザーに要確認**（意図的な省略のことが多い）。

8. **各動画は自己完結**：収録は動画1本ずつなので、次動画へのブリッジ（「次は◯◯を見ます」で終わる等）は不要/控えめにし、**その動画だけで完結する導入と締め**にする。

## C. 追加観察（第1回 動画2「AIとは何か、俯瞰する」＝技術解説回）

9. **技術回は「要点に圧縮」される**：ドラフトの細部が語られず、各スライドが短く要点化される。例＝研究者名（マッカーシー/ミンスキー/シャノン/ロチェスター）は「ダートマス会議」だけに、DIKWの「体温36.5」例や「情報リテラシー」の枠組みは省略、2-8の「AIエージェント」は触れず推論（reasoning）に集約。→ ドラフトは盛り込みすぎず、各スライド1〜2の核に絞ってよい。

10. **身近な実例・固有名を即興で足す**：ドラフトに無い具体例が口頭で入る。例＝Googleの「猫を見分けるAI」、YouTube等にAIが内蔵、アヤメ（iris）データセット、ChatGPTを名指し、学習の「ブラックボックス」性。→ 抽象説明には身近な実例の枠を用意しておくと自然。

11. **専門語は噛み砕く**：「自己回帰」などの用語よりも「次の言葉を予測しているAIと考えればOK」のように言い換える。セルフアテンション等は名前だけ出して深入りしない。

12. **締めは「自分で調べてみて」系**：動画2は「AIの活用事例をGoogle検索／AIに聞いてみて」→「ご視聴ありがとうございました」で自己完結（パターン8を再確認）。

> **内容面の検証（動画2の学び）**：口頭で即興に挙がる具体例は、技術的に不正確なことがある。例＝教師なし学習の説明で「アヤメのデータセットで品種を分類」と挙がったが、アヤメ品種分類は通常 **教師あり** の定番例。→ **ユーザー判断で原稿から削除**（2026-06-16）。反映時は、即興の具体例の妥当性を必ず確認し、怪しければユーザーに諮る。

## D. 追加観察（第1回 動画3「原則・倫理・リスク」＝規範・法律の回）

13. **実演の例がスライド間で移動・差し替えされる**：ドラフトで3-8（個人情報）にあった「看護師→患者情報」の例が、収録では3-6（公平性のバイアス例「『看護師』と入力→女性ばかり」）に移動し、3-8の入力例は「学生のレポートをAIに採点させる」に差し替わった。→ 反映時はスライドと例の対応を取り直す（draftの当てはめを鵜呑みにしない）。

14. **即興で時事・具体リスクを足す**：ドラフトに無い話が口頭で入る。例＝著作物を学習したAIの配布／吐き出し（regurgitation）、社長名義のディープフェイク被害、まとめで「AI絡みの犯罪（詐欺・性的出力で大学生が逮捕）」への注意喚起。→ リスク回はニュース的な具体例の枠を空けておく。

15. **規範・引用の細部は落ちる**：3-3で原文の英語（dignity 等）や引用の詳しい文言は語られず要点化（パターン9を再確認）。

> **内容面の検証（動画3の学び）＝口頭の年号・数値がスライドと食い違うときは、スライド（デック本体）を正本にする**。3-9の法整備で、口頭は「2020年ごろ 総務省・経産省ガイドライン」と言ったが、デックの年表は **2024年 AI事業者ガイドライン統合（第1.0版）**（ほか 2017 AI開発GL案／2019 AI利活用原則／2025 AI推進法／2026 第1.2版・エージェント対応）。口頭の言い間違いと判断し、**スライドに合わせて原稿を修正**（2026-06-16）。→ 反映時、年号・固有名・数値は文字起こしを鵜呑みにせず、デック本体（`<deck>.md`）の該当スライドを確認して合わせる。
