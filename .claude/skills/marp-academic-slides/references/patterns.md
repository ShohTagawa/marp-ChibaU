# Slide Patterns

10種類のスライド型。各パターンに **用途・最小コンテンツ・文字数上限・Markdownスニペット・拡張のヒント** を載せる。
パターンは `<!-- _class: <name> -->` で適用する。

## ヘッダーの構造（重要）

ヘッダー帯には3要素が並ぶ：
1. **デックタイトル** — 発表全体のタイトル。frontmatter `header:` で **1回だけ** 設定。
2. **ページタイトル** — そのスライド固有のタイトル。スライド本文の冒頭で `<div class="page-title">○○</div>` と書く。
3. **ロゴ** — frontmatter `header:` の `<img class="hdr-logo">` で設定。

つまり、各スライドでヘッダーをまるごと書き直す必要はない。frontmatterで1回設定、各スライドはページタイトルだけ `<div class="page-title">` で書く。

cover / divider / message / qa はヘッダー帯を表示しないので page-title も書かない（書いても表示されない）。

## 縦配分と横並び（全パターン共通の整え方）

位置の微調整を **px で1枚ずつ書かない**。次の2つで「アンカー固定・中身だけ再配置」する。

### 縦：見出し/takeaway を固定し、間を配分

見出し(`##`)と `<div class="takeaway">` は固定アンカー。その「間」を `<div class="body">…</div>` で囲み、配分はクラスで選ぶ。takeaway が無くても下端まで同じ。

| 書き方 | 挙動 |
|---|---|
| （無指定） | 上詰め |
| `<!-- _class: vcenter -->` | 間を上下中央 |
| `<!-- _class: vspread -->` | 上下に均等配分 |

```markdown
<!-- _class: vcenter -->
<div class="page-title">…</div>

## 見出し（固定）

<div class="body">

- 内容（ここだけ再配置される）

</div>

<div class="takeaway">要点（固定）</div>
```

`summary` は `.sections`、`split` は `.split-body` がそのまま「間」として効くので、`<!-- _class: summary vcenter -->` のようにクラスを足すだけでよい（`.body` で包む必要はない）。

### 横：等幅・等高の列

兄弟ブロックの幅・高さを揃えるときは `<div class="cols">` で囲む（インラインの `display:flex; flex:1` を1枚ずつ書かない）。

```markdown
<div class="cols">
<div class="box-info">左：自動で等幅・等高</div>
<div class="box-accent">右：内容が長くても高さが揃う</div>
</div>
```

上揃えにしたいときだけ `<div class="cols top">`。

## P1: 表紙（cover）

**用途**：デックの最初。タイトル・サブタイトル・発表者・日付・所属。
**ヘッダー帯**：なし。
**最小コンテンツ**：タイトル＋発表者＋所属。
**文字数**：タイトル ≤ 30字（理想 ≤ 20字）、サブタイトル ≤ 50字。

```markdown
<!-- _class: cover -->

# {{発表タイトル}}

## {{サブタイトル}}

### {{発表者氏名}}
### {{所属}}

<div class="meta">
{{YYYY年MM月DD日 / イベント名}}
</div>

<!-- スピーカーノート：自己紹介と謝辞 -->
```

---

## P1b: 標準の表紙（cover-hero）★これを既定で使う

**用途**：`chiba-deck`・実運用の**標準表紙**。中央に大タイトル、下段に丸写真＋イベント/日付/発表者。`cover` より圧倒的に使われる（実測 cover-hero 164 / cover 8）。新規デックの表紙は原則これ。
**ヘッダー帯**：あり（下線は全幅）。

```markdown
<!-- _class: cover-hero -->

<div class="title-hero">
<div class="title-small">{{上段の小見出し}}</div>
<div class="title-big">{{メインタイトル}}</div>
</div>

<div class="title-foot">
<div class="title-photo"><img src="./src/figXX-portrait.png" alt="発表者"></div>
<div class="title-meta">
<div class="title-event">{{イベント名・日時・会場}}</div>
<div class="title-name">{{発表者名}}</div>
<div class="title-affil">{{所属・肩書}}</div>
</div>
</div>

<!-- スピーカーノート -->
```

- **`theme: tsutawaru-academic` では発表者名を `.title-name`、所属を `.title-affil` で書く**（名前46px・所属24px。タイトル88px／前置き33px も既定）。日付だけを1行に置くときは従来どおり `.title-date`。
- 写真が無いときは `.title-photo` ごと省略してよい。
- 「達成目標」などを中央に置きたいときは `<div class="goal-box" style="max-width:820px; margin:6px auto 0;">…</div>` を足す構成が定番。

## 自己紹介（intro）

**用途**：演者紹介。名前（ふりがな付き）、所属、役割の説明、研究/興味分野を2カラムで。
**ヘッダー帯**：あり。page-title は「自己紹介」。
**最小コンテンツ**：氏名、所属、左右カラム両方に内容。

```markdown
<!-- _class: intro -->

<div class="page-title">自己紹介</div>

<div class="intro-head">
<div class="intro-name">
<span class="ruby">たがわ　しょう</span>
田川　翔
</div>
<div class="intro-affil">
<strong>所属：</strong>{{大学名}}<br>
{{部局/センター名}}
<div class="role">{{役割や仕事の一言説明}}</div>
</div>
</div>

<div class="two-col">
<div class="col">

### ①{{経歴トピック1}}

![{{図のalt}}]({{図パス or プレースホルダー}})

</div>
<div class="col">

### ②{{経歴トピック2}}

{{2-4行の説明文}}

</div>
</div>

<!-- 経歴の流れと今回の発表との繋がりを話す -->
```

## ①図表中心型（fig）

**用途**：1枚の図・表・グラフを主役にして語る。最下部にテイクアウェイ（固定位置）。
**ヘッダー帯**：あり。
**最小コンテンツ**：見出し＋図表＋テイクアウェイ（3点必須）。
**文字数**：タイトル ≤ 20字、テイクアウェイ ≤ 43字、表セル ≤ 15字。

```markdown
<!-- _class: fig -->

<div class="page-title">{{ページタイトル ≤14字}}</div>

## {{スライドの見出し ≤20字}}

<div class="fig-area">

![{{グラフ説明}}]({{画像パス}})

</div>

<div class="caption">図1. {{図のキャプション}}</div>

<div class="takeaway">{{要点メッセージ ≤43字}}</div>

<!-- どの数値に注目させるかを口頭で補足 -->
```

**表バージョン**（画像の代わりに表）：`.fig-area` の中に Markdown 表を置く。

**手描き SVG 図を直書きする時**：density-guide.md「インラインSVG図解の作法（見切れ防止）」の5原則（文字幅見積もり・viewBox内に収める・並列枠の文字数を揃える・主役は矢印接続・原寸で目視確認）に従う。

**画像が無い時**：

```markdown
<div class="fig-area"><div class="placeholder">[ここに○○のグラフ]</div></div>
```

## ②テキスト要約型（summary）

**用途**：複数観点を整理して示す。各観点を角丸ボックスで区切る。
**ヘッダー帯**：あり。
**最小コンテンツ**：セクション 2-3 個。各セクション 2-4 箇条書き。
**文字数**：セクション見出し ≤ 14字、各箇条 ≤ 43字。
**注意**：セクション 1 個なら別パターン（fig や split）に変える。

```markdown
<!-- _class: summary -->

<div class="page-title">{{ページタイトル}}</div>

## {{タイトル ≤20字}}

<div class="sections">

<div class="sec-box">

### {{セクション見出し1}}

- {{要点1 ≤43字}}
- {{要点2 ≤43字}}
- {{要点3 ≤43字}}

</div>

<div class="sec-box">

### {{セクション見出し2}}

- {{要点1 ≤43字}}
- {{要点2 ≤43字}}

</div>

</div>

<!-- 各セクションの相互関係を言葉で繋ぐ -->
```

---

## ③左右分割型（split）

**用途**：図と説明を並べて見せる。図 50% + 箇条書き 50%。下部にテイクアウェイ（固定位置）。
**ヘッダー帯**：あり。
**最小コンテンツ**：左に図/表、右に箇条書き3項目以上、下部テイクアウェイ。
**文字数**：右側見出し ≤ 20字、各箇条 ≤ 43字、テイクアウェイ ≤ 43字。

```markdown
<!-- _class: split -->

<div class="page-title">{{ページタイトル}}</div>

## {{タイトル ≤20字}}

<div class="split-body">
<div class="left">

![{{図alt}}]({{画像パス}})

<div class="caption">図1. {{キャプション}}</div>

</div>
<div class="right">

### {{右側見出し}}

- {{要点1 ≤43字}}
- {{要点2 ≤43字}}
- {{要点3 ≤43字}}
- {{要点4 ≤43字（任意）}}

</div>
</div>

<div class="takeaway">{{全体メッセージ ≤43字}}</div>
```

---

## ④メッセージ型（message）

**用途**：1メッセージで聴衆の注意を引きたい時。問いかけ・宣言・キーフレーズ。
**ヘッダー帯**：なし。
**最小コンテンツ**：メッセージ 1 行。サブメッセージ任意。
**文字数**：メッセージ ≤ 30字、サブメッセージ ≤ 43字。

```markdown
<!-- _class: message -->

# {{中心メッセージ ≤30字}}

## {{サブメッセージ ≤43字（任意）}}

<!-- このスライドで一拍置く -->
```

---

## 章扉（divider）

**用途**：章の区切り。背景を赤にして章番号と章タイトルを大きく。
**ヘッダー帯**：なし（背景全面が赤）。

```markdown
<!-- _class: divider -->

<div class="chapter-num">CHAPTER {{章番号}}</div>

# {{章タイトル}}

## {{章の一言サマリ ≤30字}}

<!-- この章で扱うトピックを口頭で予告 -->
```

---

## まとめ（wrap）

**用途**：発表全体の要点を ✓ チェック付きで箇条書きにする。
**最小コンテンツ**：要点 3-5 項目。各項目はその章の核を1行で。
**文字数**：各要点 ≤ 43字。

```markdown
<!-- _class: wrap -->

<div class="page-title">まとめ</div>

## まとめ

- {{P○の要点 ≤43字}}
- {{P○の要点 ≤43字}}
- {{P○の要点 ≤43字}}
- {{P○の要点 ≤43字}}

<!-- 発表全体のメッセージを再強調 -->
```

---

## 参考文献（refs）

**用途**：参照した論文・書籍リスト。APAスタイル。

```markdown
<!-- _class: refs -->

<div class="page-title">参考文献</div>

## 参考文献

- 著者A, 著者B (2024). タイトル. *ジャーナル名*, 12(3), 45-67. https://doi.org/...
- 著者C (2023). *書名*. 出版社.
- Author D, Author E (2025). Article title. *Journal Name*, 5(2), 123-145.
```

**項目が10件超**：ページ分割（refs を複数枚に）。フォントは小さくしない。

## Q&A / おわり（qa）

```markdown
<!-- _class: qa -->

<div class="page-title">Q&amp;A</div>

# Q&A

## {{メール / SNS / プロジェクトURL}}
```

## パターン選択フローチャート

| 伝えたいこと | 推奨パターン |
|---|---|
| 数値・データの示唆 | ① fig |
| 図と説明を対比 | ③ split |
| 複数観点の整理 | ② summary |
| 1つの強いメッセージ | ④ message |
| 章の切り替え | divider または message |
| 結論の集約 | wrap |
| 演者紹介 | intro |
| 開始・終了 | cover / qa |

迷ったらまず **fig** または **split**。情報密度を上げやすい。

## 講義・研修デックの定番要素（添削履歴からの一般則）

オンデマンド講義（情報リテラシー等）や FD/研修デックでは、以下が「毎回手で足される」要素。最初から入れる。

### 「なぜ学ぶか」エピソード（導入）

- 章の導入に `.episode` 枠で**実際に起きた事件・障害を学習者の日常視点**で1つ入れる（例：Cloudflare障害で X・ChatGPT が同時ダウン→「原因は自分のスマホ？それとも何？」）。
- 問いの形は**学習者が実際に抱く疑問**にする（教員側の「教えたいこと」の言い換えにしない）。出典必須。
- 抽象概念は**身近なメタファー**で先に接地する（TCP/IP=宅配便、IPアドレス=住所、ポート=部屋番号、ルーター=郵便局の仕分け。学生アンケートで最有効と確認済みの型）。

### ワークスライドの作法

- タイトルに**通し番号**（「ワーク①」）を必ず入れ、後続スライドの参照もこの番号で揃える。
- ワーク冒頭に**自己紹介タイム**を明記（1人30秒目安）。グループ再編成の直後も同様。
- 問いは**穴埋め形式**が好み（例：HMW「どうすれば◯◯が◯◯できるか？」の空欄埋め）。
- **結果の記入先**（スプレッドシート等のURL/QR）をワークのステップ内に明示する。
- 発表は「短く・一言で」。狙いは**解決策より本音（＝イシュー）の共有**、という枠づけにする。
- デック完成時に**セッション時間の合計を検算**する（「全部で90分になってますか？」が定番確認。時間配分表＝クラスデザインシートを添えると喜ばれる）。

### オンデマンド講義のクロージング

最終スライドに：
1. `band`（黄色系）で「🎬 視聴おつかれさまでした。」
2. `takeaway` で**次回・小テストの予告**（「第N回の授業内に、今回の内容の小テストを行います」）

### 動画の埋め込み

- `<video>` は **width を固定**（実績値：`width="580"`）。書き出しで崩れる場合は静止画フォールバックを用意。
- キャプションは**ページ下部**へ。動画を大きめにし、キャプションと分離する。
- 表紙級の動画（video-hero）はサイズ指示が細かく入りやすい：大きめ＋下部キャプションを既定にする。

### 配布物のAI透明性表記

配布する ipynb・ドキュメントの末尾に、**生成AI利用の透明性表記**を入れる（実績の型：「本資料は Claude Opus で作成し、Fable で検証しました。内容の責任は田川にあります」）。スライド側でも制作過程に言及してよい。

## 完成前の全数検証（3点セット）

デックを「完成」と言う前に、fan-out で以下3つを回す（添削セッションでユーザーが毎回指示していた内容＝先回りする）：

1. **PNG全数目視**：見切れ・被り・スカスカ・デザイン破綻（本ファイルと density-guide.md の基準で辛口に）
2. **ファクトチェック**：引用・数値・曜日・URL・略語展開を一次ソースで検証
3. **聴衆ペルソナレビュー**：想定聴衆（学部1年生／大学院生／教員 等、デックの対象に合わせる）のエージェントに「わかりにくい点・変な言い回し・変な比喩」を指摘させ、AIっぽい過剰演出を除く

指摘は「現在の内容は大きく変えずに」直すのが既定（構成の組み替えはユーザー承認を取る）。
