# ポンチ絵 デザイン言語

「枠を並べて中を塗る」だけの図は地味で読みにくい。ポンチ絵は **地（背景ゾーン）→ 図（部品）→ 文字** の三層を意識し、奥行き・アイコン・フローで「読む前に伝わる」状態を作る。

## 配色（3色＋ニュートラル）

| 役割 | 変数 | 例 | 使いどころ |
|---|---|---|---|
| primary | `--accent` | #1A7A5E | 主役・帯・ゴール・矢印 |
| primary濃 | `--accent-dark` | #125642 | グラデ終端・影色・反転帯 |
| primary淡 | `--accent-soft` | #E4F2EC | ゾーン背景・カード地 |
| 注意/課題 | `--warn` | #E07B39 | 問題・リスク・Before |
| 注意淡 | `--warn-soft` | #FBEDE2 | 課題ゾーンの地 |
| 文字 | `--ink` / `--muted` | #1f2937 / #6b7280 | 本文 / 補足 |

色は **3系統まで**。原色多用は安っぽい。彩度は中庸に、淡色で面を作り、濃色で要点を締める。

## 構図テンプレ（骨格を1つ選ぶ）

1. **横3幕フロー**：①課題 →②打ち手 →③ゴール を左→右。幕間を太いシェブロンで繋ぐ。因果を語る構想に最適（学長ピッチ向き）。
2. **ハブ&スポーク**：中央に主役ノード、周囲に要素。「繋ぐ/統合」を語るとき。
3. **ロードマップ旅**：左下→右上へ昇る曲線パスに番号ノード。段階・成長を語るとき。
4. **階層ピラミッド/レイヤー**：土台→中間→頂点。基盤の上に価値が積層する構造。
5. **Before→After**：左右2分割、中央に変換矢印。導入効果を語るとき。
6. **バックボーン＋ヒーロー結節点（流れ可視化の本命）**：左→右の太いリボン（バックボーン）を主骨格に敷き、その**クリティカルパス上の1点だけ**をグロー＋反転帯で中心ノードに浮かせる。横3幕（方向性）とハブ（中心の着地点）の**いいとこ取り**。「複数の流れが1つの基盤に集まり、そこから価値が出ていく」構想に最適。

1枚の中で **主骨格1つ＋補助1つ** まで。例：上段を横3幕フロー、下段をロードマップ旅。

## 骨格の選び方（判断基準）

**「左上→右下か、中央で目立たせるか」は二択ではなく、可視化したい“動詞”で決まる。** まず「この絵で伝えたい動作は何か」を一語にする。

| 伝えたい動詞 | 選ぶ骨格 | 理由 |
|---|---|---|
| 流れる・段階・順序・因果（A→B→C） | 横3幕フロー / ロードマップ旅 | **流れには向きがある**。読む順＝情報の順にすると視線負荷が最小 |
| 統合する・集約する・繋ぐ・ハブになる | ハブ&スポーク | 「中心との関係」が一瞬で伝わる。ただし**順序・前後は消える** |
| 積み上がる・基盤の上に乗る | 階層ピラミッド | 土台→頂点の上下で価値の積層を示す |
| 変わる・効果（導入前後） | Before→After | 左右対比＋中央の変換で差分を示す |
| 流れ **かつ** 1点に集約（両方欲しい） | **バックボーン＋ヒーロー結節点（#6）** | 流れを殺さず着地点も1つ作れる。役員ポンチ絵の本命 |

**原則：主題が「情報の流れ（flow）」なら方向性レイアウト（左→右／下→上）が勝つ。** ハブは“統合”は強いが順序を消すので、flow が主役のときは中心一極に逃げない。両方欲しいときだけ #6。

### Web知見で裏取りした原則（流れ可視化）

- **ポンチ絵＝ビジュアル主体レイアウト → Z字（方向性）が適合**。テキスト主体なら F字スキャンだが、ポンチ絵は図が主役なので左上→右下の動線で組む。
- **選んだ経路の焦点位置（左上＝起点/ロゴ、終端＝ゴール）に重要要素を置き、焦点を連ねて視線を段階誘導する**。要素をばら撒かない。
- **役員向けは15秒〜1分で要旨が立つこと**。上部にタイトル＋1〜2行サマリ、下部に結論帯。中央は本体。
- **アクセント（強調色／反転／グロー）は“焦点1つ”だけに使う**。複数を目立たせると着地点が消える＝のっぺり化。
- **色・形にカテゴリのルールを決める**（例：accent=主役/我々、warn=課題、グレー=外部）。読む前に意味が区別できる。

## 三層レイヤリング（描く順）

1. **地：ゾーン背景** — 角丸の大パネル（淡色塗り）/ 斜め帯 / グラデ面 / 淡い放射グロー。意味のかたまりごとに「面」を先に置く。
2. **図：部品** — カード（影付き）・アイコンバッジ・番号ノード・矢印・数字。
3. **文字** — 見出し（大・太）／本文（中）／補足（小・muted）。

地の上に図、図の上に文字。**境界線で四角く囲うのを基本にしない**。面の塗り分けと影で領域を分ける。

### 0層：背景ヒーロー画像（文字の裏に半透明で“地”を語る）

ゾーン背景のさらに下に、主題を表す画像を**ごく薄く**敷ける。読む前に「何の話か」を空気で伝える層（図書館・分子・キャンパス・回路など）。

```xml
<!-- 最下層に1枚。header帯より後ろ・本体より前 -->
<image href="./src/hero.png" x="0" y="98" width="1280" height="492"
       opacity="0.10" preserveAspectRatio="xMidYMid slice"/>
<rect x="0" y="98" width="1280" height="492" fill="#ffffff" opacity="0.55"/> <!-- スクリム：本文の可読性を担保 -->
```

ルール（可読性最優先）：
- **不透明度 0.06–0.12**。これ以上濃いと本文コントラストが落ちる。濃くしたいときは上に白スクリム（opacity 0.5前後）を1枚重ね、その上に文字。
- **細かい文字の真下に高コントラストな絵を置かない**。画像は「静かなゾーン」に寄せるか、`radialGradient` マスクで本文密集部に向けてフェードアウトさせる。
- ブランド調にするなら `feColorMatrix` で accent 系のダクトーン（単色化）にすると馴染む。原色写真の貼り込みは安っぽい。
- **役割は“文脈・主題の合図”であって精密データではない**。重要な数字・ラベルを背景画像だけに載せない（消える）。アクセントの焦点1つは前面の図形側に置く。

## 奥行きの作り方

- **ドロップシャドウ**：カードは `filter` の `feDropShadow`(dy3, blur5, accent 0.15〜0.2) で浮かせる。
- **グラデ**：帯・主役ノードは線形グラデ（accent→accent-dark）。平面の単色塗りより立体的。
- **グロー**：主役の背後に放射グラデの淡い円を敷くと視線が集まる。
- **線は控えめ**：枠線は使うなら 1〜1.3px・淡色。濃い太枠で囲わない。

## アイコン原則

- 各かたまりに **1つだけ** アイコン。円バッジ（accent 塗り or soft 塗り）の中に白/濃色のグリフ。
- 抽象1筆書きレベルでよい（人・本・AIチップ・的・建物・歯車・矢印・電球）。`svg-library.md` に雛形。
- アイコンは「装飾」でなく「索引」。文字を読まずに意味が立つことが目的。

## フロー（流れ）の描き方

- 幕間の矢印は **細線でなく塊**（シェブロン三角 or 太いリボン）。`marker-end` の細矢印は補助線のみに使う。
- 因果は左→右 or 下→上で一貫。逆流させない。
- 「繋ぐ/統合」は曲線で合流させる（複数線が1点に集まる）。

## タイポグラフィ階層

| 要素 | px | 太さ |
|---|---|---|
| ポンチ絵タイトル(計画名) | 26–30 | 700 |
| 幕見出し/ゾーン見出し | 15–18 | 700 |
| キーメッセージ(帯) | 19–22 | 700 |
| 本文 | 13–15 | 400/700 |
| 補足・ラベル | 11–12.5 | 400 |
| 巨大数字(KPI主役) | 34–48 | 700 |

- 最小 **11px**。色コントラストで階層を作る（濃=要点、muted=補足）。
- 反転（濃地に白文字）を帯・主役に使うとメリハリが出る。

## 余白とリズム

- 外周マージン 32–40px。要素間 12–20px。詰めすぎず、ゾーンの「間」を残す。
- 整列：左端・中心線を揃える。バラバラの座標は散漫に見える。
- 1280×720 を上下に帯（タイトル/結論）＋中央に本体、の三段構成が安定。

## やってはいけない（地味化の原因）

- 全要素を同じ太枠の四角で囲う（＝のっぺり）。→ 面塗り＋影で分ける。
- 4色以上の原色。→ 3系統に絞る。
- 細矢印だけで流れを示す。→ 塊の矢印を主役に。
- アイコン無しの文字だけ。→ 各かたまりに索引アイコン。
- 中心(主役)が無い。→ ハブ/巨大数字/ゴールのどれかを視線の着地点に。
