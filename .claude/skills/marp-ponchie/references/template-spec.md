# ポンチ絵 テンプレ自動生成の構造（宣言スペック → 描画）

**狙い**：作者（or LLM）は **「中身＋動詞」だけを JSON で宣言**し、座標・図形・矢印はエンジン（=この手順）が決める。ピクセルを手で置かない。AntV の宣言的インフォグラフィック / SmartArt の「カテゴリ＝意図別レイアウト」/ Sankey・swimlane の「flow の種類分け」を1つに統合した型。

パイプライン：**spec(JSON) → 意図解決(動詞→骨格) → レイアウト関数(スロット座標を算出) → 三層描画(地→図→文字) → 出力PNG目視**。

---

## 1. キャンバス定数（全パターン共通の枠）

1280×720。上下に帯、中央に本体の三段（design-language の「余白とリズム」に準拠）。

| ゾーン | y範囲 | 役割 |
|---|---|---|
| `header` | 0–62 | タイトル（左・25–30px白）＋ロゴ（右上） |
| `summary` | 62–98 | 1–2行サマリ帯（accent-soft地・16px）。15秒で要旨が立つ一文 |
| `body` | 110–590 | 本体。骨格がここを占有（上段=主骨格／下段=補助骨格に2分割可） |
| `conclusion` | 600–676 | 結論帯（シェブロン形・反転・20px白）。視線の最終着地 |

外周マージン 40px / 要素間 12–20px。

## 2. スペック・スキーマ（作者が書くのはこれだけ）

```jsonc
{
  "meta": {
    "title":      "「研究×学び」AIエージェント基盤 構想",  // header
    "summary":    "教員を増やさず院生の研究力を引き上げる", // summary帯・1行
    "conclusion": "課題を解くハブとなり研究力が伸び続ける大学へ", // conclusion帯
    "logo":       "./src/chiba-logo.png",
    "palette":    "green"          // ponchie.css のトークン束（green/blue…）
  },
  "intent": "flow",                // ←動詞。これが骨格を決める（§3）
  "body": { /* 骨格ごとに形が違う（§4） */ },
  "aux":  { /* 任意：下段の補助骨格。同じく intent+body 形 */ }
}
```

ルール：**色・形のカテゴリは tone で宣言**（`accent`=主役/我々, `warn`=課題/リスク, `muted`=外部/前提）。読む前に意味が区別できる（霞が関流ポンチ絵の鉄則）。

## 3. 意図解決テーブル（動詞 → 骨格）

SmartArt 8カテゴリ＋flow3分類を、design-language の6骨格に写像。**まず「伝えたい動作」を一語に**。

| intent（動詞） | 骨格 | 出典系統 | 流れの向き |
|---|---|---|---|
| `flow` 流れる・順序・因果 | 横3幕フロー | Process / flowchart | 左→右 |
| `handoff` 誰が何を渡す | スイムレーン | swimlane | 左→右＋レーン |
| `magnitude` どれだけ流れる | リボン（太さ=量） | sankey | 左→右・幅で量 |
| `integrate` 統合・集約・繋ぐ | ハブ&スポーク | Relationship/radial | 中心へ集約 |
| `flow+integrate` 流れ＋1点集約 | **バックボーン＋ヒーロー結節点(#6)** | 合成 | 左→右＋中央グロー |
| `stack` 積み上がる・基盤の上 | 階層ピラミッド | Pyramid | 下→上 |
| `compare` 変わる・導入前後 | Before→After | Comparison | 左↔右＋中央変換 |
| `cycle` 回る・継続 | サイクル環 | Cycle | 円周 |
| `journey` 段階・成長 | ロードマップ旅 | Timeline/Process | 左下→右上 |
| `list` 並列・順不同 | カードグリッド | List | なし（整列のみ） |

**原則**：主題が flow なら方向性レイアウト。flow と集約の両取りだけ #6。逆流させない。

---

## 4. 骨格別スロット定義（body の形 と 自動配置の規則）

各骨格は「body の配列長 N」を受けて、レイアウト関数がスロット矩形を等間隔で算出する。`tone` で色、`icon` で索引バッジ（svg-library の雛形ID）。

### flow（横3幕） — `stages[]`（2–4）
```jsonc
"body": { "stages": [
  { "no":1, "label":"なぜ必要か", "tone":"warn",   "icon":"warn",  "lines":["…","…"] },
  { "no":2, "label":"なぜできるか","tone":"accent", "icon":"chip",  "lines":["…"] },
  { "no":3, "label":"向かう先",    "tone":"accentFill","icon":"target","lines":["…"] }
]}
```
配置：本体幅 1200 を N枚＋(N-1)シェブロンで分割。各カード `panel(影付)`＋`gradHeader(tone)`＋`iconBadge`＋見出し＋`lines`。幕間に **塊シェブロン**（細矢印でなく三角）。最終カードは `accentFill`（反転）でゴール強調＝着地点1つ。

### integrate（ハブ&スポーク） — `hub` ＋ `spokes[]`
```jsonc
"body": { "hub": {"label":"AIエージェント基盤","icon":"chip"},
          "spokes":[ {"label":"学修履歴","icon":"db"}, … ] }
```
配置：中心に `gradNode+glow` の主役、周囲に spokes を円周等配。各 spoke→hub へ **曲線で合流**（複数線が1点へ）。着地点=中心。

### flow+integrate（#6 バックボーン＋ヒーロー結節点） — `stages[]` ＋ `hero`
```jsonc
"body": { "stages":[…左→右の幕…],
          "hero": {"onStage":2, "label":"基盤","glow":true} }
```
配置：flow と同じ左→右バックボーンを敷き、`hero.onStage` の位置 **だけ** に glow＋反転帯。流れを殺さず着地点を1つ作る。**役員ポンチ絵の既定値**。

### stack（ピラミッド/レイヤー） — `layers[]`（下→上）
```jsonc
"body": { "layers":[ {"label":"データ基盤","tone":"muted"}, … {"label":"価値","tone":"accentFill"} ] }
```
配置：下=広く土台、上=狭く頂点。最上層を反転で締める。

### compare（Before→After） — `before` / `after` / `delta`
```jsonc
"body": { "before":{"label":"導入前","lines":[…],"tone":"warn"},
          "after": {"label":"導入後","lines":[…],"tone":"accent"},
          "delta": "AIが伴走" }
```
配置：左右2分割＋中央に変換矢印（delta ラベル）。

### journey（ロードマップ旅） — `milestones[]`
```jsonc
"body": { "milestones":[ {"no":1,"label":"…","sub":"…"}, … ] }  // 左下→右上の昇る点線パスに番号ノード
```

### list / cycle / handoff / magnitude
- `list`: `cards[]` を 2×2 / 1×N グリッドに等配（順序なし）。
- `cycle`: `steps[]` を円周に等配＋周回矢印。
- `handoff`: `lanes[]`（役割）×`steps[]`、レーン帯で「誰が」を可視化。
- `magnitude`: `flows[]{from,to,weight}`、weight をリボン幅にマップ（Sankey）。

### aux（下段の補助骨格・任意）
`body` と同じ形をもう1つ。例：上段 `flow`＋下段 `list`（受益者カード）。**1枚に主骨格1＋補助1まで**。

## 5. 描画コントラクト（エンジンの出力順＝三層）

```
1. <defs>           ← svg-library のグラデ/影/marker を palette で実体化
2. header band + title + logo
3. summary band + 一文
4. resolve intent → 骨格 → layout()でスロット矩形[]を算出
5. body: 各スロット = zone地(面塗り) → 部品(card/icon/arrow) → 文字   ※太枠で囲わない
   ├ aux があれば body を上下2分割して同様に
6. conclusion band（シェブロン形・反転）
7. </svg> → PNG出力して目視（§design-language チェックリスト）
```

不変条件（エンジンが守る）：
- アクセント／反転／glow は **焦点1つだけ**。複数を目立たせない。
- 流れは塊矢印・一方向。逆流させない。
- 各かたまりにアイコン1つ（索引）。色は3系統以内。
- SVG内に空行を作らない（Marp が段落分割する）。

## 6. 最小サンプル（flow+integrate を1スペックで）

```jsonc
{
  "meta": { "title":"研究×学び 基盤構想", "summary":"教員を増やさず研究力を上げる",
            "conclusion":"基盤に集約し研究力が伸び続ける大学へ", "palette":"green" },
  "intent": "flow+integrate",
  "body": {
    "stages": [
      {"no":1,"label":"課題","tone":"warn","icon":"warn","lines":["院生↑・多様化","教員は増えない"]},
      {"no":2,"label":"基盤","tone":"accent","icon":"chip","lines":["実践知＋情報を統合"]},
      {"no":3,"label":"GOAL","tone":"accentFill","icon":"target","lines":["手間↓×研究力↑"]}
    ],
    "hero": {"onStage":2, "glow":true}
  },
  "aux": { "intent":"list", "body":{ "cards":[
    {"label":"学生","icon":"user","lines":["個別伴走で研究力↑"]},
    {"label":"教員","icon":"users","lines":["定型をAIが肩代わり"]},
    {"label":"大学","icon":"building","lines":["データ統合でIR活用"]}
  ]}}
}
```

→ エンジンが §1–5 を適用し、既存 onepager と同じ構造のSVGを生成する。**作者が触るのは中身と動詞だけ**。

## 7. コンサル流「1枚集約」（Minto / MBB）

役員ポンチ絵は **ピラミッド原則**で組む。「考えるのはボトムアップ、見せるのはトップダウン＝答えから言う」。1枚への落とし込み：

| 位置 | コンサル要素 | ポンチ絵での実装 |
|---|---|---|
| header/summary（上） | **アクション・タイトル＋ガバニングメッセージ** | タイトルは“結論を述べる完全文”。summary帯に「答え」を1行（topic でなく conclusion） |
| body（中） | **MECE な3支柱（横ロジック）** | `stages`/`cards` を **3±1** に。重複なし・漏れなし。横方向で並列に読める |
| conclusion（下） | **So-What（だから何）** | 結論帯に「だから〜な大学へ」。各ゾーンにも小さな so-what 一文 |
| 物語 | **SCQA**（状況→複雑化→問い→答え） | flow骨格の ①課題→②打ち手→③GOAL がそのまま SCQA |

鉄則：**1枚＝1メッセージ**。支柱は MECE で3つに割る（4超は認知負荷で割る合図）。「答え→根拠」の順で、読み手の時間を奪わない。

## 8. 密度コントロールと文字オートフィット

> 「情報を詰めつつスペースを埋める。文字サイズをどうするか」への回答。

**大原則：文字を縮めて詰めるのではない。`情報単位`を先に予算化し、文字は離散スケールの“収まる最大段”に自動で寄せる。** 下限割れは「縮める」でなく「レイアウトを変える」合図（infolit デッキの縦オーバーフロー教訓と同じ）。

### 8.1 情報単位の予算（先に上限を決める）
- 1枚の総ユニット = `骨格スロット数 × スロット内行数`。目安：**主骨格 3±1 スロット × 各 2–3 行**＋補助 4 カード × 1–2 行。
- これを超えたら **文字を縮める前に**：①支柱を MECE に統合して数を減らす ②2枚に割る ③補助骨格を落とす。

### 8.2 タイプスケール（自由pxを禁止し、段階トークンに固定）
design-language のタイポ階層を**離散スケール**化。オートフィットはこの段の中だけで動く（fitty 流＝マジックナンバー無し）。

| トークン | px段 | 用途 |
|---|---|---|
| `kpi` | 48 / 40 / 34 | 主役の巨大数字 |
| `title` | 30 / 28 / 26 | 図タイトル |
| `key` | 22 / 20 / 19 | キーメッセージ帯 |
| `head` | 18 / 16 / 15 | ゾーン/幕見出し |
| `body` | 15 / 14 / 13 | 本文 |
| `label` | 12.5 / 12 / 11 | 補足・ラベル（**11が下限**） |

### 8.3 box-fit アルゴリズム（各テキストスロット）
1. テキスト幅を概算：`幅 ≒ 文字数 × fontPx × 係数`（全角≈1.0, 半角≈0.55）。
2. スロット幅に**収まる最大の段**をそのトークン内で選ぶ（大→小に降りる二分探索）。
3. **`label` の下限 11px でも溢れる → 縮めない**。代わりに：折返し行を増やす／スロットを広げる／支柱を1つ削る／2枚に割る、を提案。
4. 見出し系（title/key/head）は溢れにくいので段固定でよい。揺らすのは body/label のみ。

### 8.4 「スペースを埋める」の正解（余白は設計、文字で埋めない）
余白が寂しいときに**本文を拡大して埋めるのは禁止**（読みにくく安っぽい）。埋め方の優先順：
1. **ヒーローを大きく**：主役の巨大数字／ゴールノードを `kpi` 段で拡大し“間”を構造化。
2. **地（ゾーン背景）で面を埋める**：淡色パネル・グラデ帯・放射グローで領域を満たす（三層の「地」）。
3. **スロットを justify 伸縮**：カード自体を等間隔で広げる（テキストは据え置き、箱が伸びる）。
4. **索引アイコン／補助図版を足す**：文字でなく図で密度を上げる。
5. それでも余る → **情報を足せる合図**：so-what の一文、根拠データ、補助骨格を1つ追加。

### 8.5 密度チェック（出力後の目視に追加）
- [ ] 支柱は MECE で 3±1 か（横に並列で読めるか）
- [ ] 本文/ラベルは離散スケール段に乗っているか（中途半端なpx無し）
- [ ] 11px 下限割れで詰めていないか（割れたらレイアウト変更したか）
- [ ] 余白は「地・ヒーロー・図」で埋め、本文拡大で埋めていないか
- [ ] アクセント（強調）は焦点1つに保たれているか
