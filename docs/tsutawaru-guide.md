# tsutawaru-academic — 『伝わるデザインの基本』準拠テーマの使い方

『伝わるデザインの基本 増補改訂3版』（高橋佑磨・片山なつ／技術評論社）のルールで、
スライドの**本文（メイン領域）だけ**を組み直すテーマ。
ヘッダー帯・ロゴ・page-title・ページ番号・フォントは `academic.css` のまま変えていない。

本文中の `p.NNN` は書籍のノンブル。すべて紙面で現物を確認した箇所だけを引いている。

---

## 1. どのテーマを使うか

| theme | 用途 |
|---|---|
| `academic` | 土台。単独で使うのは純学術デックのみ |
| `chiba-deck` | 既存の実運用テーマ（109デック）。部品が多く、囲みが増えやすい |
| **`tsutawaru-academic`** | **新規デックの推奨。囲みを最小化し、太さ・余白・揃えで構造を作る** |

`tsutawaru-academic` は `academic` を `@import` している。`chiba-deck` とは**併用しない**（役割が競合する）。

### ビルド

```bash
DECK=slides/<deck-name>
npx @marp-team/marp-cli@latest "$DECK/<deck-name>.md" --no-stdin \
  --theme-set theme/academic.css theme/tsutawaru-academic.css \
  --html --images png --allow-local-files -o "$DECK/out/<deck-name>.png"
```

`--html` と `--no-stdin` は必須（CLAUDE.md 参照）。PDF は `tools/marp-pdf/build-pdf.sh` を使う。

## 2. テーマが自動で守る数値

| 項目 | 既定 | 根拠 |
|---|---|---|
| 色数 | 背景・文字・メインの3色。強調色は1色 | p.190 合計4色まで／p.192 3色に／p.196 強調色は1色 |
| 文字色 | `#262626`（黒ではない） | p.193・p.198 黒より明度を数〜10%上げた灰 |
| メインの色 | `#A6192E`（えんじ寄りの赤） | p.184・p.205 原色／彩度の高すぎる色を使わない |
| 文字サイズ | 見出し34px／本文23px／補足19px | p.77 4種類以上のサイズを使わない |
| ジャンプ率 | 34 ÷ 23 = 1.5 | p.160 |
| 行間 | 1.7（＝文字サイズの0.7文字分） | p.62 0.5〜1文字分／p.203 1.5倍程度 |
| 字間 | 0.05em（＝5%） | p.67 5〜10% |
| 行長 | 28文字（本文幅は画面の約55%） | p.80 スライドは1行20文字前後／p.179 16:9では幅の1/2〜2/3 |
| 段落後 | 0.5行 | p.78（空白行では空けない） |
| 小見出しの後 | 0 | p.78 小見出しには段落間隔を設定しない |
| 囲みの丸み | 3px（全部品で統一） | p.98 丸みは最低限・統一する |
| 囲みの内側余白 | 1文字分（短い語句は0.5文字分） | p.106・p.107 |
| 表の罫線 | 上端・見出し下・下端の3本。縦罫0本 | p.136 |
| セル内余白 | 文字サイズと同程度 | p.139 |
| 揃え | 左揃え（中央揃えを既定にしない） | p.70・p.148 上と左は必ず揃える |
| 影・グラデーション | すべて無効 | p.104 消すべき装飾は影／グラデ／枠線／立体感 |

## 3. 囲みたくなったら

> 「囲みすぎは絶対にNGです。」（p.212）
> 「枠を付けるのは最低限にしましょう。」（p.174）

本が示す代替は3段階。**③で足りるなら②も①も使わない。**

```html
<!-- ① 塗りだけ（枠線なし）— p.212「枠線を減らして塗りだけで囲む」 -->
<div class="fill">…</div>

<!-- ② 白地＋細い枠だけ（塗りに色を付けない）— p.100「色は塗りか枠のどちらか一方」 -->
<div class="rule-box">…</div>

<!-- ③ 囲まない。余白と揃えでグループを作る — p.220「枠で囲むのではなく、余白を使ったグループ化」 -->
<div class="group">…</div>
```

**塗りと枠の両方に色を付けない**（p.100）。囲みの形は資料内で1種類に統一する（p.97）。

### 実測

田川先生の添削が入った4デック（253枚）では、**84%のスライドが囲み0個**、3個以上はわずか5.5%。
一方リポジトリ全体の平均は **1.35枠/枚**。lint のしきい値（3個で警告）はこの分布から決めている。

## 4. 部品カタログ

構造は「囲み」ではなく**太さ・余白・揃え**で作る（p.174・p.220）。

| クラス | 用途 | 根拠 |
|---|---|---|
| `.blist` + `.t` / `.d` | 小見出し（同サイズの太字）＋説明（細字）。記号もインデントも使わない | p.205 の After そのもの |
| `.sh`／`h3` | 節の小見出し。短い縦罫＋メインの色の太字。囲まない | p.161 の良い例 |
| `.lead` | このスライドの主張1文 | p.181 1スライド1メッセージ |
| `.note` / `.cap` | 補足・キャプション（19px） | p.202 重要度の低い情報は小さく |
| `.fill` / `.rule-box` / `.group` | 囲みの3段階（前節） | p.212 |
| `.flow` + `.fbox` + `.arw` | フロー図。白地・細枠・直角・等幅、矢印は小さな黒三角 | p.206・p.111・p.103 |
| `.datarow` + `.num` / `.unit` | 横罫だけのデータ行。数字は大きく、単位は約半分 | p.207・p.46 |
| `.tcols` / `.tcols.fig-left` | 2カラム。16:9で行長を伸ばさないための基本形 | p.208・p.214 |
| `.figrow` | 等幅・等高・間隔均等に並べる | p.175 枠は揃えて配置 |
| `.mark` | 下線マーカー強調 | p.55 許可される装飾／p.208 の作例 |
| `.hl` / `.em` | 色の強調（1枚に1箇所） | p.196 強調色は1色／p.161 強調は最低限 |
| `<table class="zebra">` | 行が多い表を1行おきの薄い背景で区切る | p.137 |

強調の手段は**太さ・大きさ・色の3つだけ**（p.52）。**併用は2つまで**（p.76）。
輪郭・影・立体感・反射は使わない（p.52）。

### 既存デックからの移行

`theme:` を `chiba-deck` から `tsutawaru-academic` に変えるだけで、
`box-accent` / `box-info` / `box-warn` / `callout-*` / `stepbox` / `pcard` / `goal-box` などの
既存の囲みが**落ち着いた1形式**（薄い塗り＋左の細罫、影なし、丸み3px統一）に寄る。
そのうえで lint を回し、囲みが3個以上のスライドを `.blist` や `.group` に置き換えていく。

## 5. グラフ

`marp-echarts` スキルの手順はそのまま。テーマだけ `tsutawaru` を指定する。

```bash
node tools/echarts-render/render.mjs \
  slides/<deck>/src/figNN-<name>.chart.mjs /tmp/figNN.svg 760x400 --theme tsutawaru
```

焼いた SVG は `.tcols` の左カラムなどに**インラインで直書き**する（`<img src="*.svg">` は PDF/PNG で空白になる）。

| ルール | 根拠 |
|---|---|
| 強調するのは1系列だけ。他はグレーに落とす（`focusColors()` を使う） | p.140 |
| 項目数は概ね6まで | p.123 |
| 目盛りは粗く（既定 splitNumber 4）、区切りは丸い数字に | p.208 |
| 凡例を往復させず、系列や棒に値・名前を直接添える | p.198 色のみに頼らない |
| 影・角丸・立体感・余計な目盛線は付けない | p.132・p.104 |
| 軸線は黒、目盛線は薄い横罫だけ | p.134・p.132 |
| 折れ線のプロットは●、円グラフの区切りは白い枠線 | p.126・p.127 |
| 赤と緑の対比を避け、オレンジや青を使う（暖色×寒色＋明度差） | p.195 |
| 同じデータを表とグラフで二重に出さない | p.140 |

> **既知の落とし穴：フォント名は単一引用符で書く。**
> ECharts の SSR は `font-family` を `style="…"` 属性にそのまま埋め込むため、フォント名を
> **二重引用符**で書くと属性が途中で閉じ、スライドにインライン埋め込みしたときに
> **グラフの文字が全部消えることがある**。
>
> 実測（同一 option・同一CSSで引用符だけ変えて比較）：
> `"BIZ UDPGothic","Hiragino Sans","Hiragino Kaku Gothic ProN","Yu Gothic Medium","Noto Sans JP",…`
> の5書体指定では軸ラベル・データラベルが**全消失**。単一引用符にすると正常に出た。
> 一方、旧 `chiba-theme.mjs` の3書体指定（`"Hiragino Sans","Yu Gothic",YuGothic,"Noto Sans JP",…`）では
> 消えずに描画されていた（既存デックに埋め込み済みのグラフは無事。実物で確認済み）。
> **書体の並び次第で出たり消えたりするので、常に単一引用符で書く。** 両テーマとも修正済み。

## 6. 文体（※ここだけ本の範囲外・このリポジトリの運用ルール）

本はレイアウトの本で、文体には触れていない。以下は「AIが書いたように見える」を避けるための運用ルール。

**体言止めで止めない。述語で言い切る。**

| 避ける | 直す |
|---|---|
| 生成AIの教育現場への活用 | 生成AIを授業でどう使うかを決める |
| 学習効果の可視化と評価の高度化 | 学習の成果を測れるようにする |
| 組織的な推進体制の構築 | 誰が何をするかを先に決める |

`〜化` `〜性` `〜力` `〜点` `〜の実現` `〜の推進` `〜の向上` で行を止めない。

**煽らない。誇張語を外し、事実と根拠で言う。**

避ける語：革命／激変／衝撃／圧倒的／劇的／必見／今すぐ／驚異／覚醒／淘汰／乗り遅れ／
ゲームチェンジ／パラダイムシフト／爆速／最強／完全版／徹底解説／決定版／もはや／ついに

**AIっぽい常套句を使わない。**

避ける言い回し：〜に他ならない／〜ではないでしょうか／〜と言えるでしょう／
極めて重要／不可欠／〜が求められています／〜していく必要がある／単なる〜ではなく

## 7. lint

```bash
node tools/tsutawaru-lint.mjs slides/<deck-name>            # 1デック
node tools/tsutawaru-lint.mjs slides --summary              # 全デックの集計だけ
```

| レベル | 何を見るか | しきい値の根拠 |
|---|---|---|
| `error` | 18px 未満の font-size | CLAUDE.md の不変則 |
| `warn` | 囲み3個以上／可視文字400字超／文字サイズ4種類以上／角丸8px超 | p.174・p.202・p.77・p.98＋実測分布 |
| `info` | 中央揃え | p.70 |
| `style` | 体言止め・煽り語・AIっぽい常套句 | 本の範囲外（第6節） |

**lint は目視の代わりにならない。** 編集したら必ず `--html` 付きで PNG を出し、
該当ページを開いて (a) 意図した変化が出ているか (b) 見切れ・被りがないか を確認する（CLAUDE.md）。
