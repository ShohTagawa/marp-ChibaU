# 情報リテラシ 第9回 授業設計＋台本（対面90分）

## この回について

本回は **千葉大学 工学部1年（医工学／都市環境システム／応用化学）** を対象とした、**対面90分（火4）** の授業である。設計の基本原理は **「8-20-90の法則」**——すなわち、開始 **8秒** で学生の関心を一気につかみ（冒頭のお詫び＋驚きのある要約で巻き込む）、約 **20分ごと** に「講義（解説）」と「ワーク（手を動かす・ペアで話す）」のモード（活動）を切り替えて集中の山を作り直し、**90分** を1セッションの認知的上限とみなして詰め込みすぎないよう全体を設計する。本回は第8回（TCP/IP・ネットワーク基礎）の知識を「メール／Web／暗号」という具体に橋渡しし、NotebookLM・Gem・Colab（netlab1/2）で実際に手を動かしながら定着させる「応用・統合回」と位置づける。

## ステップ別 台本

### ステップ1 (2分・講義) 第1タームお礼＋配信遅れのお詫び

**教員の語り**
> 「みなさん、第1タームお疲れさまでした。まずお詫びです——オンデマンド配信が遅れてしまって、本当にすみませんでした。今日はその分も含めて、ネットワークの知識を『自分のメール』『自分のWeb』で動かして確かめる、手を動かす回にします。机の上はPC1台あればOKです。」

**ねらい**：謝罪で心理的な距離を縮め、同時に「今日は受け身ではなく実習回だ」という期待値をセットする。
**8-20-90の切替**：冒頭8秒のつかみ（お詫び＝意外性で注意を集める）。

### ステップ2 (8分・講義) 第8回の要約3枚

**教員の語り**
> 「前回の地図を3枚で一気に思い出します。1枚目、ネットワーク全体像。2枚目、TCP/IPの4層とカプセル化——荷物を箱に入れて、さらに大きな箱に入れていくイメージでしたね。3枚目、IP・DNS・サブネット。DNSは『名前から住所を引く電話帳』でした。ここまで、ついてこれる人?」

**ねらい**：本回の土台となる第8回の核（4層・カプセル化・DNS）を高速で再活性化する。
**8-20-90の切替**：講義パートの立ち上げ（最初の約20分ブロックの前半）。

### ステップ3 (10分・ワーク) ワーク① マイワーク（ペア）

**前提**：第8回スライドを各自NotebookLMに投入済み（→ プロンプトP1）。隣同士でペアを作る。
**3つのタスク**：①TCP/IPを宅配便などのアナロジーで相手に説明 ②第8回で気になった点を質問し合う ③二人で「ネットワークの良い学び方」を考える（→ プロンプトP2）。

**教員の語り**
> 「ペアを作ってください。最初に1つだけ——なぜ『たとえ話』が学びに効くのか。脳は新しい概念を、すでに知っているもの（宅配便）に結びつけると記憶に残ります。だから今日は、TCP/IPを宅配便のたとえで相手に1分で説明してみてください。詰まったらNotebookLMに『宅配便で例えて』と頼んでOKです。」

**ねらい**：説明することで理解の穴を発見させる（アナロジー＋ピアティーチング）。AIを"説明の壁打ち相手"として使う型を体験させる。
**8-20-90の切替**：講義→ワークへの最初のモード切替（約20分目）。

### ステップ4 (12分・講義) メール技術の解説

**教員の語り**
> 「では、その『ネットワークの上を実際に流れるもの』の代表、メールです。送るときは **SMTP**、受け取るときは **POP** か **IMAP**。役割が分かれています。メールには封筒の外側にあたる『ヘッダ』があって、誰から誰へ・どの中継を通ったかが全部書いてあります。**MIME** で画像も送れる。そして——Fromは簡単に詐称できる。これが『なりすまし』の正体です。」

**ねらい**：プロトコルの役割分担と、ヘッダ＝メールの履歴書という見方を与え、次のワークの題材を仕込む。
**8-20-90の切替**：ワーク→講義へ戻す（新しい約20分ブロックの開始）。

### ステップ5 (8分・ワーク) ワーク② メールヘッダを読む

**教員の語り**
> 「自分のGmailを開いて、適当なメールの右上『︙』から『メッセージのソースを表示』。出てきた呪文のような文字列がヘッダ全文です。これをそのままGem-Aに貼って、解説させてみましょう。誰から誰へ、どこを中継したか、Fromは詐称されていないか——AIが翻訳してくれます。」（→ プロンプトP3）

**ねらい**：抽象的だった「ヘッダ」を自分の実データで読む。AIを"難解テキストの通訳"として使う。
**8-20-90の切替**：講義→ワーク（手を動かす）。

### ステップ6 (10分・講義) ssh / HTML / JavaScript の解説

**教員の語り**

**ねらい**：「人が遠隔操作する（ssh）」と「機械が読む文書（HTML/JS）」を区別し、DevToolsワークへ橋渡しする。
**8-20-90の切替**：ワーク→講義（新ブロック開始）。

**ねらい**：Webの裏側を可視化し、AIを"段階的に教えてくれる制作コーチ"として使う成功体験を作る。

### ステップ9 (講義) TLS/SSL/HTTPS の解説

**教員の語り**
> 「さっきメールヘッダは丸見えでしたね。ネットの通信は、何もしなければ『平文』——盗み見られます。それを防ぐのが **HTTPS**。鍵マークの正体です。仕組みは公開鍵を使った『ハンドシェイク』と、相手が本物だと示す『証明書』。難しそうですが、次のColabで実際に暗号化してみます。」

**ねらい**：これまで見てきた「平文の怖さ」を回収し、暗号化＝HTTPSの必然性を理解させる。
**8-20-90の切替**：ワーク→講義。
