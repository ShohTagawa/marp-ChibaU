# ビッグデータ

<div class="subhead"><span style="color:var(--accent-dark)">単なる「大量のデータ」ではない、新しい価値の源泉</span></div>

<div style="font-size:23px; margin:4px 0 10px;">従来のソフトウェアの処理能力を超える規模のデータ（3つのV）</div>

<div style="display:flex; gap:24px; align-items:flex-start;">

<div style="flex:1;">
<div class="goal-box" style="font-size:23px; padding:12px 24px; margin:6px 0;"><b>Volume(量):</b> テラ・ペタバイト級の蓄積</div>
<div class="goal-box" style="font-size:23px; padding:12px 24px; margin:10px 0;"><b>Variety(多様性):</b> テキスト、音声、動画など</div>
<div class="goal-box" style="font-size:23px; padding:12px 24px; margin:10px 0;"><b>Velocity(速度):</b> リアルタイムで生成・更新</div>
</div>

<div style="flex:1; display:flex; flex-direction:column; gap:12px;">
<div class="box-info" style="margin:0;">
<b>社会へのインパクト</b><br>

</div>
<div class="box-warn pip-safe" style="margin:0;">

</div>
</div>

</div>

# <span style="color:var(--accent-dark)">科学的推論の3つのアプローチ</span>

<div style="display:grid; grid-template-columns:auto 1fr 1fr 1fr; gap:10px 14px; margin-top:8px; align-items:stretch;">

<div></div>
<div class="callout-gray" style="text-align:center; padding:8px 0;"><b>帰納法</b><br><span style="font-size:21px;">(Induction)</span></div>
<div class="callout-gray" style="text-align:center; padding:8px 0;"><b>演繹法</b><br><span style="font-size:21px;">(Deduction)</span></div>
<div class="callout-gray" style="text-align:center; padding:8px 0;"><b>アブダクション</b><br><span style="font-size:21px;">(Abduction)</span></div>

<div></div>
<div style="font-size:20px; text-align:center; padding:0 6px;">複数の個別データや事実から、共通する一般的な法則を導き出す推論。</div>
<div style="font-size:20px; text-align:center; padding:0 6px;">一般的な法則や前提ルールから、論理的に個別の結論を導き出す推論。</div>
<div style="font-size:20px; text-align:center; padding:0 6px;">観察された結果に対して、最も妥当な説明を仮説として推論する。</div>

<div style="font-weight:800; color:var(--accent-dark); align-self:center;">利点</div>
<div class="box-info" style="font-size:20px; text-align:center; padding:8px 10px; margin:0;">検証可能・再現可能・論理的必然性</div>
<div class="box-info" style="font-size:20px; text-align:center; padding:8px 10px; margin:0;">現実的、理論がなくても可</div>
<div class="box-info" style="font-size:20px; text-align:center; padding:8px 10px; margin:0;">新しい仮説を生み出せる</div>

<div style="font-weight:800; color:var(--accent-dark); align-self:center;">欠点</div>
<div class="box-warn" style="font-size:20px; text-align:center; padding:8px 10px; margin:0;">前提次第、新しさに乏しい</div>
<div class="box-warn" style="font-size:20px; text-align:center; padding:8px 10px; margin:0;">確実ではない、白いカラス</div>
<div class="box-warn" style="font-size:20px; text-align:center; padding:8px 10px; margin:0;">仮説が複数あり得る、確証バイアス</div>

</div>

<div class="takeaway pip-safe" style="margin-top:12px;">複数のアプローチを組み合わせて解決を目指す</div>

<!--
- 科学的推論には3つのアプローチがある。帰納法は個別データから一般的法則を導く。演繹法は一般的法則から個別の結論を導く。アブダクションは結果に対し最も妥当な仮説を推論する。
- 利点と欠点もそれぞれ違う。帰納法は検証・再現可能だが前提次第。演繹法は理論がなくても可だが確実ではない。アブダクションは新しい仮説を生めるが確証バイアスに注意。
- 一つに頼らず、複数のアプローチを組み合わせて解決を目指す。
-->

# <span style="color:var(--accent-dark)">科学研究のふたつのアプローチ(パラダイム)</span>

<div style="margin-top:6px;">
<div class="box-info" style="margin:6px 0;"><b>仮説駆動型:</b> 仮説からの予測を実験・観測によって検証する</div>
<div class="box-accent" style="margin:6px 0;"><b>データ駆動型:</b> 実験・観測データから法則性をみつける</div>
</div>

<table style="font-size:22px; margin-top:10px; width:calc(100% - var(--pip-w));">
<tr><th>項目</th><th>仮説検証型のアプローチ</th><th style="color:var(--accent);">データ駆動型のアプローチ</th></tr>
<tr><td>出発点</td><td>仮説を立てる</td><td>蓄積された膨大なデータ</td></tr>
<tr><td>進め方</td><td>仮説 → 実験 → 検証</td><td>データ → 解析 → 発見</td></tr>
<tr><td>特徴</td><td>「仮説が正しいか？」を検証する</td><td>「次に何が起こるか？」を予測</td></tr>
</table>

<div class="takeaway pip-safe" style="margin-top:14px;">データ駆動型のアプローチはより容易に</div>

<!--
- 科学研究には、ふたつのアプローチ(パラダイム)がある。仮説駆動型は仮説からの予測を実験・観測で検証する。データ駆動型は実験・観測データから法則性をみつける。
- 出発点・進め方・特徴を比べると、仮説検証型は「仮説が正しいか」を検証し、データ駆動型は「次に何が起こるか」を予測する。
- ビッグデータの時代には、データ駆動型のアプローチがより容易になっている。
-->

# <span style="color:var(--accent-dark)">メール作成時の主なアドレスの種類</span>

<table style="font-size:21px; margin-top:10px; width:100%;">
<tr><th style="width:140px;">項目名</th><th>意味</th></tr>
<tr><td><b>From</b></td><td>[必須] 送信者のアドレス (差出アドレス) <span style="color:var(--accent); font-weight:800;">※詐称可能</span></td></tr>
<tr><td><b>To</b></td><td>[原則、必須] 受信者のアドレス (宛先アドレス) (必要に応じて返信すべき)当事者</td></tr>
<tr><td><b>Cc</b></td><td>Carbon copy の略。上司など、To以外の人に参考までにメールを送信するときに指定する。</td></tr>
<tr><td><b>Bcc</b></td><td>Blind carbon copy の略。Bccのアドレスは他の受信者には見えないので、流出を防ぐ時に使用 ※ To/Ccにはbccが見えない → トラブル注意。</td></tr>
<tr><td><b>Reply-To</b></td><td>返信先を指定する場合</td></tr>
</table>

- Fromは必須の送信者アドレスだが詐称可能。Toは原則必須の受信者アドレス。Ccはカーボンコピーで上司など参考までに送る人。
- BccはブラインドカーボンコピーでアドレスがTo/Ccの受信者には見えないので流出防止に使うが、見えないこと自体がトラブルの元になるので注意。Reply-Toは返信先を指定する場合に使う。

# メール件名のマナーとネチケット

<div style="display:flex; gap:24px; align-items:flex-start; margin-top:6px;">

<div style="flex:1;">
<div class="callout-pink" style="font-weight:800; padding:6px 16px;">件名： Subject</div>
<div style="font-size:21px; margin:8px 0 0 6px; line-height:1.6;">
本文の内容を<b>的確かつ簡潔に</b>表現する。<br>
用件がひと目で分かるようなタイトルをつけることが重要。<br>
多数のメールを受信する人の立場を考えましょう。
</div>

<div class="box-warn" style="margin-top:12px; font-size:21px;">
<b>空（件名なし）でメールを送るのはマナー違反</b><br>
読まずに後回しにされたり、迷惑メールと間違われて捨てられてしまうこともあります。
</div>
</div>

<div style="flex:1;">
<div class="callout-pink" style="font-weight:800; padding:6px 16px;">行頭の「Re:」や「Fwd:」</div>
<div style="font-size:21px; margin:8px 0 0 6px; line-height:1.6;">
メールソフトやWebメールが自動的に付ける記号。書換え・追加しない。
</div>

<div class="box-info" style="margin-top:12px; font-size:21px;">
<b>Re:</b> 返信を示す（ラテン語の "res" が語源）<br>
<b>Fwd:</b> 転送 (Forward) を示す。添付の場合と(全文)引用の場合があり。
</div>
</div>

</div>
