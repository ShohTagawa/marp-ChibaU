## 要旨（Abstract）

大規模言語モデル（LLM）はK–12（初等・中等）教育の現場に急速に投入されつつある。しかし C-Eval、CMMLU、GaokaoBench、EduEval といった既存ベンチマークが測っているのは「試験問題に答えられるか」、すなわち**事実の想起**だけである。

実用的な教育AIには、それに加えて**カリキュラム認知（curriculum cognition）**が要る。知識がどう組織され、どう視覚的に提示されているかの構造的な理解——前提知識の連鎖、概念の分類体系、実験と概念の結び付き、教育的な配列順序——である。カリキュラム認知は、現行のベンチマークで測られてもいないし、現行の指示チューニングデータで明示的に教えられてもいない。

このギャップを埋めるため、本研究は **K12-KGraph** を提案する。中国の検定教科書（人民教育出版社）から抽出した、カリキュラム整合型のナレッジグラフである。数学・物理・化学・生物の4教科を、小学校・中学校・高校の全段階にわたって覆う。**9種のノード型**（Book, Chapter, Section, Concept, Skill, Experiment, Exercise, Figure, VisualElement）と、カリキュラム構造と視覚的接地の双方にまたがる**14種の関係型**をもつ。

この単一のグラフから、相補的な2つのリソースを導出する。

- **K12-Bench**：グラフ由来の5タスク族（Ground, Prereq, Neighbor, Evidence, Locate）からなる23,640問の複数選択ベンチマーク。カリキュラム認知を多角的に検査する。
- **K12-Train**：KG誘導による教師ありファインチューニング（SFT）コーパス7,335件（K12-Train-Full）。うちテキストのみ2,267件（K12-Train-Text）、マルチモーダル5,068件（K12-Train-MM）。

実験は、明確なギャップと明確な処方箋の両方を示した。K12-Bench では、強力なプロプライエタリモデル（Gemini-3-Flash）でも完全一致（EM）**57%**、強力なオープンソースモデル（Gemma-4-31B-IT）で**46%**にとどまり、なかでも Prereq と Neighbor が最難であった。一方で学習実験は、K12-Train によるドメイン特化の教師信号がこの限界を有効に埋めうることを示す。

- **LLM**：厳密に揃えた2,300サンプルのSFT予算のもとで、K12-Train-Text は主要8コーパス（OpenHermes, Infinity, UltraChat, WizardLM, DataFlow, LMSYS, SmolTalk, Tulu-3）の同サイズ部分集合を GaokaoBench・EduEval の双方で一貫して上回った。構造に接地したカリキュラムデータのサンプル効率の高さを示す。
- **VLM**：K12-Train-Full は Gaokao-MM、MDK12-medium、K12Vista の3つで、比較した全学習設定中もっとも良い総合性能を達成した。DataFlow・WizardLM の全量（10,000件・142,759件）より少ないサンプル数（7,335件）でありながら、である。さらに K12-Train-Text 単独・K12-Train-MM 単独のいずれをも上回り、テキストと視覚の教師信号が**相補的**であることを示した。

グラフ・ベンチマーク・学習データ・構築パイプラインの全てを公開する。

## 1. はじめに（Introduction）

LLMはK–12の試験問題に答えることにかけては、驚くほど習熟した。C-Eval、CMMLU、GaokaoBench、EduEval といったベンチマークでは、最先端モデルはもはや上位の人間の生徒に匹敵し、時に凌駕する。これがLLMによる個別指導・受験対策への急速な関心を煽っている。額面どおりに受け取れば、教育AIはもう解けかけているように見える。

しかし実際に指導プロダクトを作ろうとした者なら誰でも知っているとおり、**問いに答えることは、良い教師が実際にやっていることのごく一部にすぎない**。そして今日のベンチマークが検査せずに残しているのは、まさにその残り大部分のほうなのだ。

検査されていない部分を、本研究は**カリキュラム認知**と呼ぶ。すなわち、

- **なぜ**ある話題を別の話題より先に学ばねばならないのか
- 実験室での実験が理論的概念と**どう**つながっているのか
- 各アイデアが教科書の**どこ**に実際に置かれているのか

——の構造的理解である。

有能な中学1年の数学教師は、「一次方程式」が単元名であることを知っているだけではない。それが**四則演算を前提として要求する**こと、「代数式」の下で「不等式」と**兄弟関係にある**こと、そして人民教育出版社の教科書の**第3章に初出する**ことを知っている。

さらに、カリキュラムの知識は**教科書の図**を通じても伝達される。模式図、実験装置図、幾何図形、練習問題の挿図は、概念を説明したり、関係の視覚的証拠を与えたり、問題を解くのに必要な情報を供給したりする。

今日のK–12ベンチマークはどれもこの種の構造的・視覚的理解を検査しておらず、その結果として今日の学習データもそれを明示的に教えていない。**生徒を試すためではなく、生徒を支えるAIを作ることに関心があるなら、このギャップこそがボトルネックである。**

これを埋めるため、本研究はすべてを単一のリソースの上に構築する。すなわち、中国の検定教科書（人民教育出版社）から直接抽出したカリキュラム整合型ナレッジグラフである。

得られたグラフ **K12-KGraph** は異種プロパティグラフであり、数学・物理・化学・生物を小・中・高の全段階にわたって覆う。これは2つの成分からなる。

**テキスト成分**（カリキュラム構造を捉える）：7種のノード型（Concept, Skill, Experiment, Exercise, Section, Chapter, Book）と、以下を符号化する辺型。

| 意味 | 関係 |
|---|---|
| 分類（taxonomy） | `is_a` |
| 前提（prerequisite） | `prerequisites_for` |
| 関連（association） | `relates_to` |
| 検証（verification） | `verifies` |
| 評価（assessment） | `tests_concept`, `tests_skill` |
| 所在（location） | `appears_in` |
| 順序（order） | `leads_to` |

**マルチモーダル成分**（視覚的接地を捉える）：2種のノード型（Figure, VisualElement）と、構成（`contains_visual_element`）、視覚意味（`refers_to`, `illustrates`）、所在（`appears_in`）、問題の図依存（`requires_figure`）、視覚的証拠（`supports_edge`）を符号化する辺型。

グラフがカリキュラムの組織のされ方を忠実に写しているため、**近傍を辿れば評価問題になり、ノード属性と辺の意味をQAに描き下ろせば学習データになる**。単一のグラフが、カリキュラム認知を測るベンチマークと、それを明示的に教える学習セットの両方を生む。

### 貢献

1. **K12-KGraph**：中国K–12向けの、大規模・多教科・検定教科書接地のカリキュラム整合型ナレッジグラフ。再現可能なLLMベース抽出＋階層マージのパイプラインと、分類関係・前提関係に対するDAG検証を伴う。
2. **K12-Bench**：グラフ由来の複数選択問題23,640問。5つのタスク族——Ground（知識の接地）、Prereq（前提推論）、Neighbor（近傍推薦）、Evidence（実験の証拠連鎖）、Locate（章横断の索引付け）——にまとめられ、合わせて構造的なカリキュラム理解を検査する。オープンソース・プロプライエタリ10モデルを評価したところ、Gemini-3-Flash でさえEM 57%、強力なオープンソースモデル Gemma-4-31B-IT では46%にとどまった。
3. **K12-Train**：KG誘導のQA合成パイプラインが生む高品質な教育SFTサンプル7,335件。テキストのみ2,267件（K12-Train-Text）とマルチモーダル5,068件（K12-Train-MM）を含む。
   - LLMでは、厳密に揃えた2,300サンプル予算のもと、K12-Train-Text でのSFTが主要8コーパスを2つのベースモデル上で GaokaoBench・EduEval ともに一貫して上回った（例：GaokaoBench で最強のSFTベースラインに対し **+24.1 / +32.4**、公式のinstructチューニング版に対し **+114.6 / +221.0**）。
   - VLMでは、K12-Train-Full でのSFTが Gaokao-MM、MDK12-Bench、K12Vista で最良の総合性能を達成し、DataFlow・WizardLM の全量ベースライン（7,335 対 10,000 / 142,759サンプル）を、はるかに小さいサンプル数で凌駕した。K12-Train-Text・K12-Train-MM 単独の性能も上回った。

これらの結果は、**ドメイン内の教育データの価値**と、**テキストと視覚の教師信号の相補性**の両方を浮き彫りにする。

## 2. 関連研究（Related Work）

### K–12・教育ベンチマーク

中国のK–12教科でLLMを評価するベンチマークはいくつかある。**C-Eval** と **CMMLU** は広範な多分野スイートでK–12カテゴリを含むが、多肢選択の事実問題に焦点がある。**GaokaoBench** は中国の大学入学試験（高考）を対象とし、客観問題と主観問題の双方を扱う。**EduEval** は6つの教育能力次元（応用・創造性・倫理・記憶・推論・理解）を覆う。**E-Eval** と **K–12 EduBench** がさらに範囲を広げている。マルチモーダルでは **Gaokao-MM**、**MDK12-Bench**、**K12Vista** が教育問題上の視覚推論を評価する。**CK12** はナレッジグラフを取り入れているが、構造的なカリキュラム理解ではなく全体的な認知に焦点がある。

これらはいずれも**モデルが領域の問いに答えられるかを試す**ものであり、**モデルがカリキュラムの構造——前提依存、概念分類、教育的配列——を理解しているかを系統的に評価するものは一つもない**。

### 教育ナレッジグラフ

ナレッジグラフは教育分野で知識追跡（knowledge tracing）や前提関係の発見に応用されてきた。しかし既存の教育KGは、単一教科あるいは英語圏の講義に焦点があることが多く、公的なK–12カリキュラムに整合していることは稀で、一般に教科書知識をテキストの実体と関係として表現するのみで、**教科書の図を明示的に接地していない**。近年LLMによるKG構築の研究もあるが、中国K–12教科書から大規模・多教科・カリキュラム整合のKGを構築し、それをLLMのベンチマークと学習の**両方**に用いた先行研究は存在しない。

### 指示チューニングデータセット

高品質な指示データによるSFTはLLMの整合に不可欠である。OpenHermes、UltraChat、WizardLM、Tulu-3、SmolTalk といった汎用データセットは多様なタスクを覆うが、**ドメイン特化の教育知識を欠く**。Self-Instruct とその派生はLLMから合成データを生成するが、構造化された知識源を活用しない。本研究のKG誘導合成は、学習データを**カリキュラム構造に接地**させることでこのギャップを橋渡しする。

## 3. K12-KGraph

### 3.1 スキーマ設計

K–12教育に合わせた異種プロパティグラフのスキーマを設計した。テキスト成分とマルチモーダル成分の両方を含む。スキーマは**9種のノード型と14種の有向辺型**を定義する（付録7.1の表9に要約）。

各ノードは型付きのプロパティをもつ。たとえば **Concept** ノードは `name`、`definition`（教科書の文言を優先）、`importance`（understand／master／important）、および任意項目として `formula`、`aliases`、`examples` を含む。**Experiment** ノードは `instruments`（器具）、`is_student`（生徒が実施する実験か）、`process`（手順）、`phenomena`（現象）、`conclusion`（結論）を含む。

#### 表9：K12-KGraph のスキーマ（9ノード型・14関係型）

**ノード型**

| 型 | 説明 |
|---|---|
| Book | 教科書の実体（教科・学年・出版社） |
| Chapter | 章（タイトルと順序） |
| Section | 節（タイトルと順序） |
| Concept (Cpt) | 定義を伴う中核知識概念 |
| Skill (Skl) | 転移可能な方法・技法 |
| Experiment (Exp) | 器具を伴う実験 |
| Exercise (Exe) | 問題文と解答をもつ練習問題 |
| Figure (Fig) | 教科書中の1枚の図 |
| VisualElement (Vis_Ele) | 図の中で教育的価値をもつ局所的な視覚要素 |

**関係型**

| 関係 | 意味（始点→終点） |
|---|---|
| `is_a` | 分類上の包摂（Concept→Concept） |
| `prerequisites_for` (prereq) | 学習依存（Concept/Skill→Concept/Skill/Experiment） |
| `relates_to` (rel_to) | 意味的関連（Concept→Concept） |
| `verifies` (verif) | 実験による検証（Experiment→Concept） |
| `tests_concept` (tes_cpt) | 問題が概念を評価（Exercise→Concept） |
| `tests_skill` (tes_skl) | 問題が技能を評価（Exercise→Skill） |
| `contains_visual_element` | 図の構成（Figure→VisualElement） |
| `illustrates` | 図レベルの知識接地（Figure→Concept/Skill/Experiment） |
| `refers_to` | 要素レベルの知識接地（VisualElement→Concept/Skill/Experiment） |
| `requires_figure` | 視覚依存（Exercise→Figure） |
| `supports_edge` | テキスト関係への視覚的証拠（Figure→Edge） |
| `appears_in` | 知識の所在（Concept/Skill/Experiment/Figure→Section） |
| `leads_to` (lea_to) | 章レベルの必要学習順序（Chapter→Chapter） |
| `is_part_of` | 章階層（Section→Chapter、Chapter→Book） |

### 3.2 構築パイプライン

構築は5つの自動段階で進む（図1）。

1. **OCRベースのパーサ**（MinerU）が教科書PDFを構造化Markdownに変換する。見出し階層・数式・生テキスト・画像アセットを保持する。
2. **目次パーサ**が `sections_index.json` マニフェストを生成し、Markdownを節単位のファイルに分割し、各画像をその節のテキストに紐付ける。
3. 各節について、**GPT-5.2** にスキーマを意識した指示（付録7.3）を与え、ノードと辺を構造化JSONとして出力させる。あわせて全ての辺に**根拠引用**（教科書の原文）または**確信度スコア**（その関係に対するモデルの確信）を付す。
4. 節ごとのグラフを**ボトムアップにマージ**する。書籍レベルのパスがグローバル一意IDを割り当て、同名の概念・技能を重複排除し、辺を張り替える。次に教科レベルのパスが同一教科内の書籍横断で実体を突き合わせる（例：中2物理と中3物理の双方に現れる「速度」）。
5. `is_a` および `prerequisites_for` の部分グラフに**深さ優先の閉路検出**をかけ、違反を人手で解消する。これにより分類関係・前提関係について妥当なDAGが得られる。

#### 品質管理

自動DAG検証に加えて：

- 抽出プロンプトが**ハルシネーションを明示的に抑制**し、出力を「真に重要で、明確に提示された」知識に限定する。
- 辺には確信度フィールドと、元の教科書抜粋に遡る根拠フィールドを付すよう促す。
- 抽出された全トリプルを**ドメイン専門家が人手で検証**する。
- 階層的な重複排除は、軽い正規化による名称照合ののち、専門家レビューによって書籍横断の別名を突き合わせる。

## 4. K12-KGraph からのベンチマークと学習データ

K12-KGraph から、KGに接地した2つのデータセットを導出する。**K12-Bench**（§4.1）はグラフのテキスト的近傍を複数選択問題に変換し、LLMのカリキュラム認知を評価する。**K12-Train**（§4.2）はノード属性と辺の意味を構造接地されたQAペアに変換し、教育用LLMを学習させる。

図2は、単一の `prerequisites_for` 部分グラフ上で共有パイプラインを示す。パネル(A)は部分グラフが Prereq のベンチマーク項目に実体化される様子、パネル(B)は同じ関係が学習用のKG誘導QAペアに再定式化される様子を示す。

目的は異なるが、両リソースは同じ性質を利用している。すなわち、**すべてのサンプルが特定の部分グラフに遡れる**ため、難易度・カバレッジ・事実正確性を系統的に制御できる。

### 4.1 K12-Bench：ベンチマークの構築

K12-Bench は5つのタスク族（9サブタスク）からなり、それぞれが構造的カリキュラム理解の異なる側面を検査する。

**形式**：すべて複数選択（multi-select）。問題文と4つのラベル付き候補が与えられ、モデルは正解ラベルの**集合全体**を出力しなければならない。正解の個数は問い方と局所的なグラフ近傍に応じて項目ごとに1〜3個で変動するため、正解が1つの項目でも複数選択の出力形式で答えねばならない。

**問題と誤答（distractor）はLLM生成ではなくグラフ由来**である。各タスクについてテンプレートを定義し、グラフクエリで実体化する。正解は真のグラフ近傍であり、誤答は構造的に近いが答えではないノードの多層プールからサンプリングする（例：2ホップ近傍、共通の `is_a` 親をもつ兄弟ノード）。

モデルにはグラフの文脈を一切与えず問題文のみを提示するため、ベンチマークは**パラメトリックなカリキュラム知識**を検査する。

各候補集合は、文字3-gramのコサイン類似度による段階で表層的にほぼ重複するものを除去し、続いてGPT-5.2ベースの**教育的フィルタ**で正解のいずれかと同義の誤答を破棄する。

#### 5つのタスク族

| 族 | 検査する関係 | 内容 |
|---|---|---|
| **Ground**（知識の接地） | `tests_concept`, `tests_skill` | サブタスク1：問題文が与えられ、それが試す中核概念・技能を選ぶ。サブタスク2：概念・技能が与えられ、それを評価する問題を選ぶ。誤答は同一カリキュラム文脈内の構造的に関連する概念・技能から。 |
| **Prereq**（前提推論） | `prerequisites_for` | サブタスク1：概念・技能が与えられ、その前提の閉包を選ぶ。サブタスク2：概念・技能が与えられ、その最も直接的な後続を全て選ぶ。誤答は構造的に隣接するノード（関連概念、分類上の兄弟）から。 |
| **Neighbor**（近傍推薦） | `is_a`, `relates_to` | 概念が与えられ、（いずれかの向きの `is_a` または `relates_to` で）直接関連する概念を全て選ぶ。誤答は構造的に近いが近傍ではない概念、主に2ホップの外環から。 |
| **Evidence**（実験の証拠連鎖） | `verifies` | サブタスク1：概念が与えられ、それを検証する実験を選ぶ。サブタスク2：実験が与えられ、それが検証する概念を選ぶ。誤答は構造的に関連する概念または実験から。 |
| **Locate**（章横断の索引付け） | `appears_in`, `leads_to` | サブタスク1：知識実体が与えられ、それが初出する章を選ぶ。サブタスク2：章が与えられ、その前提となる章を選ぶ。誤答はカリキュラム内の代替的な構造位置から。 |

#### ベンチマークの統計と品質

K12-Bench は合計 **23,640** の複数選択項目を含む（タスク別内訳は付録8.3・表11）。

すべての項目が、LLM生成ではなく**検証済みのK12-KGraph部分グラフから決定論的に導出される**ため、その事実正確性は下敷きとなるグラフの正確性に帰着する。K12-KGraph 自体は**教科資格をもつ12名のアノテータによって全数を人手検証**されており、アノテータ間一致は高い（全体で Fleiss' κ = **0.84**、付録10）。さらに K12-Bench の層化抜き取り検査では、サンプル項目の **98.4%** が完全に正しかった。

このパイプラインは、ベンチマーク品質とグラフ品質のあいだに異例なほど緊密な連結を与える。**KGの改善はそのままベンチマークに伝播し、不具合は特定のグラフの辺に局在化できる。**

### 4.2 K12-Train：KG誘導のデータ合成

K12-Train は、相補的な3つの経路でナレッジグラフをSFTデータに変換する。

**(i) ノード接地QA（LLMプロンプト）**
Concept, Skill, Experiment, Exercise の各ノードについて、**Qwen3-235B-A22B** にそのノードの型付きプロパティに接地したQAペアを生成させる。Concept には定義・数式・例題、Skill には手順とその適用場面、Experiment には器具・現象・結論、Exercise には問題文に簡潔な段階的推論を添えたもの。これは**ノードの中身を教える**教師信号を生む。

**(ii) 辺接地QA（LLMプロンプト）**
各意味関係について、プロンプトを固有の質問テンプレートに錨づけ、答えが**関係そのものを言語化する**よう強制する。

| 関係 | 質問テンプレート |
|---|---|
| `is_a` | 「なぜ A はカテゴリ B に属するのか？」 |
| `prerequisites_for` | 「なぜ B より先に A を学ばねばならないのか？」 |
| `relates_to` | 「A と B はどう関係しているのか？」 |
| `verifies` | 「実験 E は概念 C をどう検証するのか？」 |
| `illustrates` | 「図 F は概念 C をどう説明しているのか？」 |
| `refers_to` | 「局所的な視覚要素 V は概念 C にどう対応するのか？」 |
| `requires_figure` | 「図 F は問題に対してどんな情報を与えているのか？」 |
| `supports_edge` | 「図 F は既存の関係にどんな視覚的証拠を与えているのか？」 |

これは**ノード間の構造を教える**教師信号を生む。

**(iii) 問題–評価QA（決定論的テンプレート）**
`tests_concept` と `tests_skill` は事実として曖昧さがないため、LLMを迂回して辺から直接決定論的テンプレートを埋める。これにより完全な事実接地が保証され、問題→概念/技能の部分集合についてLLMが対象関係を捏造したり言い換えたりするリスクが排除される。

#### 品質管理

ハルシネーションを最小化するため、プロンプト前に各ノードのプロパティ集合を対象QA型に関係するフィールドだけに刈り込み、確信度が閾値未満の辺を除外する。これによりLLMが無関係な属性へ漂流するのを防ぐ。プロンプトはさらに、学年相応の言葉づかいで、与えられた属性に厳密に接地し、要点となる結論を強調する構造化された解答形式で出力するよう指示する。生成後、すべてのQAペアについてJSON構造・フィールドの非空・言語の一貫性を検証する。

#### 最終データセットの構成

**K12-Train-Full** は 7,335 のQAペアを含み、解答に視覚入力を要するかどうかでモダリティ別に分割される。テキスト情報だけで答えられるものが **K12-Train-Text**、付随する図や視覚要素を要するものが **K12-Train-MM** である。

**K12-Train-Text（2,267ペア）**：はるかに大きなKG由来の候補プールから、出典バランスを取ったランダム部分抽出で選択。

| 内訳 | 件数 |
|---|---|
| Exercise 例（段階的推論つき） | 450 |
| `tests_concept` / `tests_skill` 例 | 356 |
| ノード接地QA（Concept, Skill, Experiment） | 695 |
| 関係接地QA（is_a, prerequisites_for, relates_to, verifies） | 766 |

**K12-Train-MM（5,068ペア）**：すべて関係接地QA（`illustrates`, `refers_to`, `requires_figure`, `supports_edge`）。対応する辺の確信度に基づき選択（`illustrates`・`refers_to`・`supports_edge` は 1.0、`requires_figure` は 0.8）し、目標サイズに合わせた。

このバランス調整はデータ品質を制御しつつ、生のKG由来プールの自然な偏り（例：教科書の練習問題は相対的に少ない）を緩和し、内容と関係の教師信号をモデルが一様に学ぶよう促す。控えめなサイズにもかかわらず、これら構造接地サンプルが教育SFTにきわめて有効であることを§5で示す。

## 5. 実験と結果

相補的な2つの実験を行う。
(i) 構造的カリキュラム理解を評価するため、オープンソース／プロプライエタリのLLMを K12-Bench でベンチマークする（§5.2）。
(ii) LLMとVLMを K12-Train と他の主要指示チューニングデータセットでファインチューニングし、下流の教育タスクでの性能を比較してデータの妥当性を検証する（§5.3）。

### 5.1 実験設定

#### 評価対象モデル

K12-Bench では、オープンソースLLM 5種（Meta-LLaMA-3-8B-Instruct、GLM-4.7-Flash、Ministral-3-14B-Instruct、Qwen3-32B、Gemma-4-31B-IT）と、プロプライエタリAPI 5種（GPT-4o、GPT-5-mini、GPT-5.2、Gemini-2.5-Flash、Gemini-3-Flash）を、**ゼロショット・解答のみ**の設定で評価する。

指標はタスク別の**完全一致（EM）**（予測ラベル集合が正解集合と完全に一致すること）と、**インスタンスレベル（example-based）マクロF1**。各インスタンスについて予測と正解のラベル集合上で precision・recall・F1 を計算し、インスタンス間で平均する。これにより、ラベル数の多寡によらず全ての問いが等しく寄与する。この選択はF1をEMと同じインスタンス単位に揃え、正解集合の大きい項目がマイクロ集約F1を支配するのを避け、多ラベル分類の `average='samples'` の慣行に合う。タスクレベルのスコアはそのタスク内インスタンスの平均、全体スコアはタスク横断のインスタンス数重み付き平均である。

#### ファインチューニング設定

**テキストのみの評価**：Qwen3-4B-Base と Llama3.1-8B-Base を、K12-Train-Text と8つの汎用指示チューニングデータセットで学習。全データセットを約2,300サンプルの予算に揃える。

**マルチモーダル評価**：Qwen3.5-2B-Base を、K12-Train-Full / K12-Train-Text / K12-Train-MM と、DataFlow・WizardLM の**全量**（それぞれ10,000件・142,759件）でファインチューニング。

#### テキストのみのSFTプロトコル

Qwen3-4B-Base と Llama3.1-8B-Base に**全パラメータSFT**を実施。比較対象は OpenHermes-2.5、Infinity-Instruct、UltraChat、WizardLM_evol_instruct_V2_196k、DataFlow-10K-Instruct、LMSYS、SmolTalk、Tulu-3-SFT の8種。公平性のため各ベースラインから一様に2,300件をサンプリングし、K12-Train-Text の2,267件におおよそ揃えた。

全設定で同一のハイパーパラメータ：学習率 5×10⁻⁶、コサインスケジューラ（ウォームアップ10%）、3エポック、デバイスあたりバッチサイズ1・勾配累積4、DeepSpeed ZeRO-3、bf16精度。LLaMA-Factory で実装。各バックボーンについて、2,300件に縛られない参照点として**未調整のbase**と**対応する公式instruct版**も併せて報告する。

#### マルチモーダルSFTプロトコル

Qwen3.5-2B-Base に **LoRA SFT** を実施。全設定で同一：学習率 1×10⁻⁴、コサインスケジューラ（ウォームアップ10%）、3エポック、デバイスあたりバッチサイズ4・勾配累積2、bf16精度。LLaMA-Factory で実装。未調整の Qwen3.5-2B-Base と公式instruct版も参照点として報告。

#### 評価軸

**テキスト**：GaokaoBench（公式プロトコルに従い、客観・主観問題ともに参照解答との文字列照合）と EduEval（5能力次元にわたる18タスクの部分集合。EduEval はタスクごとに評価プロトコルが不均質なため、標準化され公式に支援されているスコアリングのものに限定して比較可能性を確保）。

**マルチモーダル**：
- **Gaokao-MM**：高考8教科の画像付き多肢選択。公式プロトコルに従いルールベースで解答を抽出し正解率を報告。
- **MDK12-Bench**：6分野・5問題形式。公式のjudge補助評価パイプラインを用い、問題形式・分野を横断して集約。
- **K12Vista**：5教科、多肢選択・穴埋め・自由記述。公式プロトコルに従い K12-PEM ジャッジで解答の正しさと推論品質を評価し、形式別平均と全体平均を報告。

#### 5.3.3 分析

##### なぜ K12-Train は効くのか？

K12-Train の優位はKG誘導合成の2つの性質から来ると仮説する。

1. **構造的接地**：各QAペアは単なる事実ではなく、明示的な関係（前提、分類、関連、検証）を符号化している。
2. **教育的一貫性**：KGが公的カリキュラムを写しているため、学習分布が教育ベンチマークの暗黙の前提と整合する。

これと整合して、K12-Train の伸びが最大となるのは GaokaoBench の自由記述問題、EduEval の Ethics 次元（いずれも孤立した想起ではなく構造化された推論を要求する）、および K12Vista の自由記述QAである。

さらなる証拠は**教科横断の転移**から得られる。K12-Train は数学・物理・化学・生物の部分グラフのみから合成されているにもかかわらず、K12-Train でのSFTは**国語**で最高スコア（120.18、最強ベースライン DataFlow に対し +3.33）、**文系数学**で最良（132.00、DataFlow に対し +4.08）を達成し、歴史・地理・政治でも最上位層に並ぶ（表4）。これらの教科は K12-Train からドメイン内の教師信号を一切受けていないため、改善を内容の記憶に帰することはできない。むしろ**転移可能で構造に接地した解答スタイルの獲得**を反映しており、K12-Train がカリキュラム認知そのものを教えているという主張を支持する。

##### テキストとマルチモーダルの教師信号の相補性

K12-Train-Full は3つのマルチモーダルベンチマークすべてで最良の総合結果を達成し、Text Only・MM Only の双方を一貫して上回る。2つの教師信号源が相補的であることを示す。**テキストのみのQAはカリキュラム知識と関係レベルの推論を強化し、マルチモーダルQAはそれらの能力を図表に接地させる**。このパターンは、テキストのみの指示データが推論能力と指示追従能力を視覚言語タスクへ転移させうるという先行知見とも整合する。

## 6. 結論

本研究は、中国の検定K–12教科書から構築したカリキュラム整合型ナレッジグラフ **K12-KGraph** と、**K12-Bench**（カリキュラム認知の評価用）および **K12-Train**（KG誘導SFT用）を提案した。実験は次を示した。

1. 現行のLLMは、強い事実想起能力にもかかわらず**頑健なカリキュラム認知を欠く**（K12-Bench で強力なオープンソースモデルが46% EM）。
2. **KG誘導合成はサンプル効率が際立って高い**。テキスト・マルチモーダルの双方において、約2,300サンプルという揃った予算のもとで K12-Train-Text は主要8SFTコーパスの同サイズ部分集合を GaokaoBench・EduEval で上回り、K12-Train-Full は3つのマルチモーダル教育ベンチマークで大幅に大きい汎用データセットを上回った。
3. **テキストと視覚の教師信号は相補的**である。K12-Train-Full は3つのマルチモーダル教育ベンチマークすべてで K12-Train-Text・K12-Train-MM の双方を一貫して上回った。

これらの結果は、より有能な教育用言語モデル・視覚言語モデルを構築するうえでの**カリキュラム接地データの潜在力**を浮き彫りにする。

## 付録10：検証と品質保証

### 10.1 検証戦略・アノテータ背景・倫理

KGを中心に据えた**階層的な検証戦略**を採る。KGは自動構造チェックと**全数の人手検証**を組み合わせた最も集中的な検証を受ける。対照的に K12-Bench・K12-Train は全数の再アノテーションではなく、**的を絞った手動抜き取り検査**で検証する。

その理由は構築方法にある。K12-Bench のインスタンス（正解と誤答の双方）はLLM生成ではなくグラフ構造から決定論的に導出されるため、その正しさは大部分が下敷きのKGの正しさに帰着する。K12-Train は教師データであり、事実に接地され教育的に有用でありさえすれば、インスタンス単位の完全な正確さは必須でない。したがって、検証済みKGとの整合を確認すれば両リソースには十分である。

人手検証はすべて**ドメイン資格をもつアノテータ**が行う。4教科（数学・物理・化学・生物）を覆うため、教科ごとに3名、計**12名**を採用した。アノテータは経験ある K–12 教育実務者で、小・中・高の各段階を集合的に覆っており、細粒度の概念と段階横断のカリキュラム関係の双方を信頼して評価できる。

アノテータには、標準的な学術アノテーション慣行に従い、地域の最低賃金以上の報酬を支払っている。全データは公開教育資料に由来し、機微な個人情報を含まない。

### 10.2 KGの検証：構造チェックと人手検証

**自動構造チェック**：`is_a` と `prerequisites_for` の部分グラフ（いずれもDAGであるべき）に自動整合性チェックを行う。グラフ構築・マージ後に閉路と構造的不整合を検出する。検出された衝突は教科アノテータがレビューし、カリキュラム上の正しさに基づき辺を削除・修正・保持のいずれにするか判断する。曖昧な場合はアノテータ間の議論で決定し、標準的なカリキュラム進行との一貫性を確保する。

**人手検証**：構造的衝突の解消後、グラフ全体に全数の人手検証を実施する。各ノード・各辺を同一教科の3名が独立にアノテートする。不一致は特定され、合同レビューを通じて解消され、合意判断（保持・修正・削除）に至る。合意ラベルを最終とする。

**視覚関係のフィルタリング**：モデルが推論した各視覚関係には根拠と確信度スコアが付く。確信度で層化した検査に基づき、`refers_to` と `illustrates` は確信度 **0.85以上**、`requires_figure` と `supports_edge` は **0.95以上**を保持する。予測されたバウンディングボックスは、妥当でありかつ局在化確信度が **0.9以上**の場合にのみ保持する。関係フィルタ後、保持された `illustrates`・`supports_edge`・入力 `requires_figure` のいずれも持たず、保持された `refers_to` をもつ VisualElement も含まない Figure は削除する。保持された `refers_to` をもたない視覚要素と、使われない具象化辺参照は、接続する辺とともに刈り取る。

**アノテータ間一致（表14）**：調停前の一致を Fleiss' κ で報告。一致は構造的に明示的な関係（例：`is_a`）で高く、意味的に微妙な関係（例：`relates_to`）で低い傾向がある。調停後、最終グラフは高い適合率を達成する。**全体の κ = 0.84**。

### 10.3 K12-Bench・K12-Train の抜き取り検証

層化抜き取り検査により、K12-Bench のサンプル項目の **98.4%** が完全に正しいことを確認。

## 付録11：拡張結果と健全性チェック

- **11.1 全ベンチマーク結果**：表15がサブタスク別、表16が教科別の詳細な K12-Bench 結果。本文表3のタスク族平均の背後にある変動の源を示す。
