| 層 | AIの居場所 | 中身 | 教育基盤ゆえのメリット |

## 機能表（まとめ用・**各セルは一次資料で確認してから載せる**）

列は「対話する → 役割を固定する → つないで勝手に動かす → PCごと任せる」の段階順。

| | Chatbot（対話） | カスタムAI（役割固定） | エージェント自動化（iPaaS的：つなぐ・勝手に動く） | CLI（PCの中で何でも） | 千葉大アカウントで機密を扱えるか |
|---|---|---|---|---|---|
| OpenAI | ChatGPT | GPTs | ChatGPT Agent／AgentKit（Agent Builder）**要確認** | Codex CLI | ×（個人契約・コアサービス外） |
| Anthropic | Claude | Projects | **Cowork**（デスクトップでフォルダ・アプリを跨いで作業）**要確認** | Claude Code | ×（同上） |
| Google | Gemini | Gems | **Workspace Studio**（＋Opal） | Gemini CLI | ○ Chatbot〜iPaaS はコアサービス／**CLI は △：GCP（有償契約）経由のみ・機密不可** |

- 先生の整理（9/6）：iPaaS 列は Claude なら Projects／Cowork、Google なら Workspace Studio。→ Projects は Gems と同じ「役割固定」なので **列を1本増やして分離**（Projects＝カスタムAI、Cowork＝自動化）が誤解が少ない
- 言いたいこと：**CLI があれば原理的に何でもできる**（ファイル・アプリ・Web を横断）。iPaaS は「人が居なくてもトリガーで勝手に動く」＝手離れが売り。Chatbot は入口
- **正直に言う限界**：千葉大の基盤で CLI が使えるのは GCP 経由だけ（＝有償・機密不可）。だから今日の「組み立てる」の到達点は **Gems ＋ Workspace Studio まで**。CLI は講師デモ（本デックの制作風景）で「その先」を見せるに留め、Pause（再現）は付けない
- 最終列が「教育基盤ゆえのメリット」の結論：機能は横並びに揃いつつある。**差は "大学の契約の内側で機密を扱えるか"**
