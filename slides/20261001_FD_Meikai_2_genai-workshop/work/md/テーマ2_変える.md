# テーマ②　手順書

「既存の課題を、AIで変える」（教員2〜3名）

使う道具：Gemini アプリ（Gem を含む）と Gemini Notebook が中心です。

---

## 1. このテーマでやること

いま出している課題を、生成AIがある前提で「一段高いところに届く課題」に作り替えます。このワークが終わるとき、みなさんの手元に、次のものができあがっています。

- 改訂した課題文（学生にそのまま配れる形）
- その課題の評価の観点表（ルーブリック）
- 学生に「AIをどこで、どう使ったか」を書いてもらう記録の様式
- 既存の1コマの授業を、講義を減らし演習を増やした形に組み替えた授業計画

12月3日までに、改訂した課題を1回出すか、組み替えた1コマを1回やってみます。

## 2. 完成イメージ

提出するのは、下の **② のスライド1枚**です。① の試作は、共有できる形になっていれば、そのスライドの下部にリンクを貼って学内に共有します（任意）。

**① 試作（今日つくった現物）。** たとえば、次のようなものです。

- もとの課題文と、AIに解かせた結果の判定（A／B／C）
- 改訂した課題文（AIの利用をどの段階まで認めるかが書いてあるもの）
- 評価の観点表（観点3〜5個 × 段階3〜4段）
- 「AI利用の記録」の様式（学生が課題と一緒に提出する1枚）
- この改訂で失われるもの（1つ）

**② 提出するスライド（またはインフォグラフィック）。** 作り方は、共通ページの Step 5 をご覧ください。「12月3日までに試すこと」を必ず入れてください。

## 3. あなたの道具はどれですか

このグループは全員が同じ道具を使います。大学のGoogleアカウントで使います。

| 道具 | どこで開くか | 得意なこと |
|---|---|---|
| Gemini アプリ | `https://gemini.google.com/app` | 解かせる、書き直す、表にする |
| Gem（ジェム） | Gemini アプリの左側のメニュー、または `https://gemini.google.com/gems/create` | 指示をあらかじめ仕込んでおける、自分専用の Gemini。同僚に配れる |
| Gemini Notebook | `https://notebook.google.com/?icid=home_maincta` | 自分の講義資料を読み込ませて、その中だけで答える |

**開き方（どのシナリオも、ここから始まります）**

① ブラウザ（Chrome など）の新しいタブを開きます。

② アドレス欄に、上の表のアドレスを入力して、Enter を押します。
→ Gemini アプリは、画面の下のほうに、文章を打ち込む横長の入力欄が見えていれば、正しい画面です。

③ 画面の右上にある丸いアイコンを押して、大学のGoogleアカウントでサインインしているかを確かめます。
→ 大学のメールアドレスが表示されていれば、正しい状態です。
→ 個人のGmailのアドレスが出ていたら、大学のアカウントに切り替えてください。
→ サインインできない方は、グループの他の方の画面を一緒に見る形で進めてください。

## 5. 各シナリオ

### シナリオ1　自分の課題をAIに解かせてみる

つくるもの：「AIにどこまで解けたか」の判定

① Gemini アプリを開きます（開き方は「3. あなたの道具はどれですか」をご覧ください）。

② いま学生に出している課題文を1つ選び、そのまま入力欄に貼り付けて、送信ボタン（紙飛行機や矢印のアイコン）を押します。
→ 手元に課題文がない方は、巻末の「架空の課題文」を使ってください。

③ 出てきた答えを、グループで読みます。次の表で判定して、番号を1つ決めます。

| 判定 | 意味 |
|---|---|
| A | このまま提出されたら、合格点を付けてしまう |
| B | 合格点は付けないが、手直しすれば通ってしまう |
| C | 授業で扱った内容や、現地・資料の固有の情報が無いので、見れば分かる |

④ 続けて、次の1行を送ります。

```
この答えに、足りないものは何ですか。大学の授業の課題として、人が考えなければ書けない部分を3つ挙げてください。
```

→ 返ってきた3つが、改訂の出発点です。提出用の文書に、判定と3つを書きます。

### シナリオ2　課題を作り替える Gem をつくる

つくるもの：改訂案3つと、選んだ1案の課題文

Gem（ジェム）とは、指示をあらかじめ仕込んでおける、自分専用の Gemini のことです。一度作れば、次からは同じ指示を打ち直さずに使えます。そして、同僚に配れます。

① Gemini アプリを開きます（開き方は「3. あなたの道具はどれですか」をご覧ください）。

② 画面の左上にある「三本線」のボタンを押して、左側のメニューを開きます。
→ 左に、細長いメニューが出てくれば、正しい画面です。

③ メニューの中から、〈Gem〉にあたる項目を探して押します。
→ 画面によって「Gem」と表示されている場合と「Gem を表示」と表示されている場合があります。どちらでも同じものです。
→ 見つからないときは、ブラウザのアドレス欄に次を直接入力してください。
　 `https://gemini.google.com/gems/create`
→ 「新しい Gem」を作る画面（名前を入れる欄と、指示を入れる大きな欄がある画面）が出れば、正しい画面です。

④ 一覧の画面が出た方は、［Gem を作成］にあたるボタン（＋のボタン）を押します。

⑤ 「名前」の欄に、次のように入れます。

```
課題を作り替える伴走者（〔 あなたのお名前 〕）
```

⑥ 「指示」の大きな欄に、次の文をまるごとコピーして貼り付けます。埋めていただくのは〔担当科目名〕だけです（2か所出てきますが、どちらにも同じ科目名を入れてください）。

```
# 役割
あなたは、大学教員が授業課題を「生成AIがある前提でも成立する課題」に作り替えるのを手伝う、
確認用の伴走者です。課題を決めるのは教員です。あなたは材料をそろえる係です。
私の担当科目は、不動産学部の〔担当科目名〕です。

# 前提知識
課題の改訂には4つの型があります（大阪大学 全学教育推進機構 TLSC・浦田 2023）。
① 問題作成と試験形式の工夫（授業内でディスカッションした内容を書かせる、口頭試験、要約 など）
② 評価とフィードバック（段階的な対面評価、引用文献の実在チェック、プレゼンでQA など）
③ 課題の提出（作成過程の考察、個人的経験との統合、下書き・編集履歴の提出 など）
④ 方針の明示と周知（許可するツールの明記、シラバスへの方針明記、誠実性の強調 など）

AIの利用をどこまで認めるかは、次の5段階で表します
（AIアセスメントスケール。Perkins, Furze, Roe & MacVaugh, 2024。大阪大学 TLSC 訳）。
1 AIは使用できない（NO AI）
2 AIで構想・計画する（AI PLANNING）
3 AIとコラボする（AI COLLABORATION）
4 AIを全面活用する（FULL AI）
5 AIを応用する（AI EXPLORATION）

また、AIを使わせる前に、まず学生自身が自分の考えを書く段階を必ず置いてください。

# 手順
1. 改訂案を出す前に、まず私に4つ質問してください。
　　(a) 授業名・学年・受講人数 (b) 測りたい力 (c) 配点と提出形式 (d) 対面の時間を使えるか
　　私が答えるまで、改訂案を出してはいけません。
2. 私が答えたら、もとの課題が生成AIでどの程度代替されうるかを、3行以内で述べてください。
3. 上の4つの型から、実施できる改訂案を3つ出してください。3案は、できるだけ異なる型から選んでください。
　　各案に必ず付けるもの：
　　・使った型の番号（①〜④）
　　・AIの利用を認める段階（1〜5の番号と名称）
　　・改訂した課題文の本文（学生にそのまま配れる文章として、完成した形で書く）
　　・教員の追加作業量（小・中・大）と、その根拠を1行
4. 私が1案を選んだら、その案について、シラバスまたは課題文に載せるAI利用方針の文章（3行以内、学生に向けた敬体）を作ってください。
5. 最後に必ず「この改訂で失われるもの」を1つ挙げてください。良いことだけを述べて終わらせないでください。

# してはいけないこと
- 次の4つは提案しないでください：AIに剽窃チェックをさせる／判定ツールで判定する／
　手書き提出を強制する／学生にAI利用を強制する。
- 実在を確認できない文献名や数値を挙げないでください。
- 私が質問に答える前に、改訂案を出さないでください。
- 受講人数に対して採点が終わらない案を出さないでください。
- 学生個人の氏名・成績・家庭の情報を尋ねないでください。
　教員が誤って入力した場合は、その情報を使わず、削除するよう伝えてください。

# 出力形式
■ いまの課題がAIで代替されうる程度（3行）
■ 改訂案1／改訂案2／改訂案3
■ この改訂で失われるもの
■ 次に先生が決めること（1行）
敬体で、体言止めを使わずに書いてください。「革命」「激変」のような、あおる言葉を使わないでください。

# 最初の一言
「〔担当科目名〕の課題づくりのお手伝いをします。いまの課題文を貼り付けてください。
　まず4つ質問させていただきます。」
```

→ 大きな欄に長い文章がまるごと入っていれば、正しい状態です。

⑦ 画面の右側にある試し打ちの欄に、いまの課題文（またはシナリオ1で使った架空の課題文）を貼って送ります。
→ いきなり改訂案が出てこず、4つの質問が返ってくれば、指示文が効いています。
→ 質問が返らずに改訂案がすぐ出てきたら、「指示」の欄の手順1に「私が答えるまで、改訂案を出してはいけません。」の1行が入っているかを確かめてください。

⑧ 4つの質問に答えます。改訂案が3つ返ってきたら、グループで1案を選び、「改訂案〔番号〕でお願いします」と送ります。

⑨ 画面の ［保存］ を押します。
→ Gem の一覧に、いま付けた名前が並んでいれば、保存できています。右側で試しに動かしただけでは保存されません。

⑩ 改訂した課題文と、AI利用方針の文章をコピーして、提出用の文書に貼ります。

### シナリオ3　評価の観点表（ルーブリック）をつくる

つくるもの：改訂した課題の観点表

① Gemini アプリを開きます（開き方は「3. あなたの道具はどれですか」をご覧ください）。

② 画面の左上にある ［新しいチャット］ を押します。

③ 次の文をコピーして、入力欄に貼り付けます。埋めていただくのは〔課題文〕の1か所です。シナリオ2で改訂した課題文、または手元の課題文を貼ってください。

```
あなたは、大学の授業設計と評価に詳しいアドバイザーです。
次の課題について、評価の観点表（ルーブリック）を作ってください。

【条件】
・観点は3〜5個にしてください。そのうち1つは、必ず「人が考えなければ書けない部分」
　（授業で扱った内容との結びつき、現地や資料の固有の情報、自分の判断とその根拠 のいずれか）にしてください。
・段階は「期待を超える／期待どおり／もう一歩／不足」の4段階にしてください。
・各マスは、学生が読んで自分の位置が分かる具体的な言葉で、40字以内で書いてください。
・「適切に」「十分に」のような、判断を丸投げする言葉を使わないでください。
・表（Markdownの表）で出してください。
・AIの利用が認められている課題であれば、「AIの使い方」を観点の1つに入れてください
　（例：AIの出力をそのまま使わず、根拠を確かめて書き直しているか）。
・敬体で、体言止めを使わずに書いてください。

【課題文】
〔 ここに、課題文を貼り付けてください 〕
```

④ 送信ボタンを押します。
→ 観点が行、段階が列の表が返ってくれば、正しく動いています。

⑤ 表をグループで読み、自分たちの学生に合わない言葉を1か所だけ挙げて、続けて直すように頼みます。

⑥ できあがった表をコピーして、提出用の文書に貼ります。

### シナリオ4　「AI利用の記録」の様式をつくる

つくるもの：学生が課題と一緒に出す1枚

① Gemini アプリを開きます（開き方は「3. あなたの道具はどれですか」をご覧ください）。

② 画面の左上にある ［新しいチャット］ を押します。

③ 次の文をコピーして、入力欄に貼り付けます。埋めていただくのは〔段階〕の1か所です。シナリオ2で決めた段階（1〜5）を入れてください。決めていない方は「3」と入れてください。

```
あなたは、大学の授業設計に詳しいアドバイザーです。
学生がレポートと一緒に提出する「AI利用の記録」の様式を、A4で1枚にまとめてください。

【前提】
・この課題では、AIの利用を、AIアセスメントスケールの段階〔 1〜5 〕まで認めています。
・記録の目的は、学生を疑うことではなく、「どこでAIを使い、どこを自分で考えたか」を
　学生自身が言葉にすることです。
・記録の内容も評価の一部になることを、様式の冒頭で伝えてください。

【様式に入れること】
1. 使ったAIの名前と、使った場面（構想／下書き／校正／翻訳／その他）のチェック欄
2. 使った主なプロンプト（頼み方）を1〜3つ書く欄
3. AIの出力のうち、そのまま使わずに直した箇所と、なぜ直したかを書く欄
4. AIを使わずに自分で考えた部分は何かを書く欄
5. 「AIの出力の正しさは自分で確かめた」という確認の署名欄

【書き方の約束】
・学生に向けた敬体で書いてください。
・記入例を、各欄に1つずつ小さく添えてください（不動産の授業を想定した架空の例で構いません）。
・全体で600字以内にしてください。
```

④ 送信ボタンを押します。
→ 1〜5の欄が並んだ様式が返ってくれば、正しく動いています。

⑤ 様式をコピーして、提出用の文書に貼ります。

### シナリオ5　既存の1コマを組み替える

つくるもの：講義を減らし、演習を増やした90分の授業計画（1枚）

① Gemini アプリを開き、画面の左上にある ［新しいチャット］ を押します。

② 次の文をコピーして、入力欄に貼り付けます。埋めていただくのは〔いまの1コマの流れ〕の1か所です。手元に授業計画がない方は、巻末の「架空の1コマ」を貼ってください。

```
あなたは、大学の授業設計に詳しいアドバイザーです。
不動産学部の既存の1コマ（90分）を、生成AIがある前提で組み替えるのを手伝ってください。
授業を決めるのは私です。あなたは、選択肢と材料をそろえる係です。

【組み替えの方針】
・「記憶」「理解」にあたる説明は、学生が事前に Gemini Notebook（教員の資料を読み込ませたAI）で予習できる形に回す。
・対面の時間は、「応用」「分析」「評価」にあたる演習・議論に使う。
・学生がAIを使う段階と、使わない段階を、はっきり分ける。AIを使う前に、必ず自分の考えを書く段階を置く。
・教員の準備の追加作業は「中」までにする。受講人数は40名を想定する。

【出してほしいもの】
1. 組み替え前と後の比較表（時間配分：説明／演習／議論／振り返り の分数）
2. 組み替え後の90分の流れ（5〜7段。各段に、教員がすること・学生がすること・AIの使用の可否）
3. 事前に学生にやってもらうこと（予習の指示文。学生にそのまま配れる敬体の文章）
4. 教員が当日までに準備するもの（3つまで）
5. この組み替えで失われるもの（1つ）

【書き方の約束】
・敬体で、体言止めを使わずに書いてください。
・実在を確認できない統計や文献名を書かないでください。

【いまの1コマの流れ】
〔 ここに、いまの1コマの流れ（テーマ、扱う内容、時間配分）を貼り付けてください 〕
```

③ 送信ボタンを押します。
→ 比較表と、5〜7段の流れが返ってくれば、正しく動いています。

④ 「2. 組み替え後の流れ」をグループで読み、自分たちの教室・人数で無理があるところを1か所だけ挙げて、続けて直すように頼みます。

⑤ できあがった授業計画をコピーして、提出用の文書に貼ります。

## 6. 提出します

提出は、共有用の**スライド1枚**です（14:10 締切）。つくった試作は、共有できる形になっていれば、そのスライドの下部にリンクを貼って学内に共有します（任意）。詳しい提出先と共有のしかたは、共通ページの「提出するもの」をご覧ください。

- **提出スライド（必須）**：共通ページの Step 5 で作ります。「12月3日までに試すこと」を必ず入れてください。
- **試作へのリンク（任意）**：改訂した課題文・観点表・記録の様式・授業計画を Google ドキュメントに貼り、共有リンクを提出スライドの下部に貼ります。Gem を作った方は、Gem の共有リンクも同じように貼ります（一覧で ［共有］ → 範囲「組織内」・権限「閲覧者」 → ［リンクをコピー］）。

**12月3日までに試すことの例（このテーマ）**
- 改訂した課題を1回出し、「AI利用の記録」も一緒に提出させて、学生がどこでAIを使ったと書いてくるかを見る
- 観点表を学生に事前に配って、提出物の質がどう変わるかを見る
- 組み替えた1コマを1回やってみて、演習の時間に学生が何につまずいたかを記録する

## 7. うまくいかないとき

| 困りごと | 対処 |
|---|---|
| Gem が質問をせずに、すぐ改訂案を出してしまう | 「指示」の欄の手順1に「私が答えるまで、改訂案を出してはいけません。」があるか確かめ、なければ足して保存し直します |
| 改訂案が理想論で、採点が終わりそうにない | 「受講人数〔人数〕で、採点時間が1人5分以内に収まる案に絞ってください」と続けて送ります |
| Gem の ［共有］ が押せない | 深追いしないでください。「指示」の欄の文章をまるごとコピーして提出すれば、受け取った方が同じものを作れます |
| Gem の一覧に、作った Gem が出ない | ［保存］を押していないことが多いです。もう一度作成画面に戻り、［保存］を押します。それでも出ないときは、ブラウザの画面を再読み込みします |
| ボタンや欄が、この紙と違う名前で出ている | 名前が違っても、同じはたらきの場所です。近い名前のものを押してください |

## 8. この紙に印刷してある資料

### 架空の課題文（シナリオ1・2で、手元に課題文がないときに使います）

```
【課題】
新駅の開業が予定されている架空の都市「湊南市」の駅前地区について、
開業後に想定される地価と賃料の変化を、需要と供給の観点から1500字で論じなさい。
関係する利害関係者（地権者・既存の商店主・新規の住民・自治体）のうち、
2者以上の立場に触れること。
```

### 架空の1コマ（シナリオ5で、手元に授業計画がないときに使います）

```
科目：不動産の価格形成（2年生・40名・90分）
テーマ：地価はどう決まるか
現在の流れ：
　0〜60分　講義（需要と供給、立地と地価、公示地価と実勢価格の違い、地価に影響する要因）
　60〜80分　例題（架空の2地点の地価の違いを、要因から説明する）を各自で解く
　80〜90分　解説と、次回の予告
```

### 課題改訂の4つの型

（大阪大学 全学教育推進機構 TLSC／浦田 2023）

| 型 | 例 |
|---|---|
| ① 問題作成と試験形式の工夫 | 授業内でディスカッションした内容を書かせる、口頭試験、要約 |
| ② 評価とフィードバック | 段階的な対面評価、引用文献の実在チェック、プレゼンでQA |
| ③ 課題の提出 | 作成過程の考察、個人的経験との統合、下書き・編集履歴の提出 |
| ④ 方針の明示と周知 | 許可するツールの明記、シラバスへの方針明記、誠実性の強調 |

### AIアセスメントスケール（AIAS）の5段階

（Perkins, Furze, Roe & MacVaugh, 2024。大阪大学 TLSC 訳）

| 段階 | 名称 | 意味 |
|---|---|---|
| 1 | AIは使用できない（NO AI） | 課題の全体を、AIなしで行う |
| 2 | AIで構想・計画する（AI PLANNING） | 構想や計画の段階だけAIを使ってよい。提出物はAIなしで書く |
| 3 | AIとコラボする（AI COLLABORATION） | AIの出力を批判的に見て、直しながら使う。どこで使ったかを明記する |
| 4 | AIを全面活用する（FULL AI） | AIを使って作ることを前提にし、AIの使い方と成果を評価する |
| 5 | AIを応用する（AI EXPLORATION） | AIそのものを題材にして、新しい使い方や限界を探る |

### 課題改善の流れ（MIT）

1. いま出している課題を、AIに入力して解かせる
2. AIの答えを分析・評価する
3. AIと対話して、さらに深掘りする
4. 課題の限界と必要性を把握して、課題を見直す（AIを課題に組み込む／小テストで補う／反転授業にする）
